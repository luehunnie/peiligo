## 1. 实验设计 — 三个固定候选（D7 三候选，零胜者预设）

三候选消费**同一字段契约**（CONTENT_MODEL §20.1 表 A/B＋权重档位；PoC 侧按 §23.1 五字段落地），方案间差异仅在后端配置层（CONTENT_MODEL §22 对接点①）。三方案 × 三档规模（200／1000／5000）全组合执行；同一数据集、同一查询集（§3）、同机、同一计时方法（§4）。

### 1.1 E1 = Wagtail DB 后端 fallback（icontains 子串匹配）

- 定义：`wagtail.search.backends.database`（modelsearch 1.3.2）的 **DB fallback 路径**——逐字段 `__icontains` OR 子串匹配（上游审计 §3.4；CONTENT_MODEL §20.0 事实 4）。目标是检验"最简单方案是否已经够用"。
- **触发方式（M6.1 定稿，CONTENT_MODEL §22 E1 行授权）**：该后端按连接 vendor 分派实现（事实 10：postgresql→PG FTS 路径，其余→fallback）——`vendor=postgresql` 的连接下 fallback 不可达。故 E1 触发＝**SQLite 连接**（`sqlite://`），同一字段契约、同一查询代码路径，唯一差异＝vendor 分派，由源码机制保证（事实 10 位点：modelsearch `backends/database/__init__.py`）。
- 已知语义差异（评分输入，非契约分支，CONTENT_MODEL §20.2）：①RelatedFields 文本（部门名/标签名/词表名）结构性缺席；②boost 权重被忽略（官方 UserWarning）；③无相关度排序（回退 queryset 排序）；④StreamField body 匹配面＝存储 JSON 原文子串（含块类型键名，存在误命中面）。
- 附注（M6.3 裁决项，本批不预设）：生产库为 PostgreSQL（PRD 已定），vendor 分派下 E1 的生产落地形态（如自实现 icontains queryset 或强制 fallback 路径）留 ADR-0006 裁决；PoC 仅测 icontains 匹配语义本身的质量与延迟。

### 1.2 E2 = PostgreSQL SearchBackend ＋ `SEARCH_CONFIG='simple'`

- 定义：同一 `wagtail.search.backends.database` 后端的 PG FTS 路径，`PostgreSQL` 连接 ＋ 后端参数 `SEARCH_CONFIG='simple'`（modelsearch `backends/database/postgres/postgres.py:960`；上游审计 §3.4）。
- `simple` 不分词：中文整串成单 token（上游审计 §3.4"中文风险"行）。**不得私自换成其他 PG config 再声称 E2**——`SEARCH_CONFIG` 取值缺省、`english` 或其他内置 config 下的运行一律不算 E2 组数据。
- 需 `django.contrib.postgres` 入 `INSTALLED_APPS`（上游审计 §3.4；PG 容器按 02 S6.2：本机 Docker `postgres:16` 一次性容器，M6.2 搭建）。

### 1.3 E3 = PostgreSQL ＋ `zhparser` 扩展

- 定义：E2 同一 PG FTS 路径，改用 `zhparser` 扩展提供的中文分词 parser 构建的自定义 text search configuration（如 `CREATE CONFIGURATION … PARSER zhparser`），`SEARCH_CONFIG` 指向该自定义 config。`pg_jieba` 作附注备选（若 M6.2 实测 zhparser 不可装而 pg_jieba 可装，替代运行须在 §5 显式注明，不混称 zhparser）。
- **可装性未知 ＝ 02 §0.3 PRE-5**：zhparser 属数据库服务器运维依赖（源码编译/扩展目录权限），本批不安装、不验证。若 M6.2 环境不可行：§5 记录 **ENVIRONMENT_INFEASIBLE** ＋ 判定依据（安装命令与报错原文），**不阻塞 E1/E2**；决策规则按 §4.4 的"E3 环境不可行"分支机械执行。

### 1.4 附注：`pg_trgm` 模糊匹配

上游审计 §3.4 提及的 trigram 模糊匹配（`postgres.py:63-65`，需 `pg_trgm` 扩展）**仅作附注，不单独成组**，不进 D7 三候选裁决；若 M6.3 结论需要，作为后续增补方向记录。

### 1.5 三方案语义差异表（PoC 评分输入）

直接采用 CONTENT_MODEL §20.2 三方案语义差异表（匹配语义 / RelatedFields / boost / 相关度排序 / StreamField 匹配面 / FilterField 义务六维），该表为零胜者预设、M6.1 PoC 评分的正式输入。§3 金标集的 `notes` 列在受差异影响的条目上显式标注（如 Q09 部门名探针、Q16 跨字段词元命中、Q22 排序区分）。

## 2. 数据集构造规则 — 真实中文校园语料

### 2.1 规模分级与档间关系

- 三档：**200 / 1000 / 5000** 条（CONTENT_MODEL §23.1）。
- 档间为增量关系：**锚点页（§3.1，P001–P044 区间）必须进入每一档**；构造顺序＝先锚点页后放量页。200 档＝锚点＋真实语料优先填充；1000/5000 档在其上放量。
- 同一数据集、同一查询集贯穿三方案三档（§1.6）。

### 2.2 来源三档（对齐 02 S6.1 §2）

| 档 | 来源 | 说明 |
| --- | --- | --- |
| a（首选） | 项目负责人/总管理员提供的真实历史通知**脱敏**文本 | M6.2 开工前向项目负责人请领；已脱敏为接收条件 |
| b | 学校官网**公开**通知的标题与正文摘录 | 采集后强制过滤：手机号/工号/学号/身份证正则 ＋ 人工复核；人名一律以职务代称（"辅导员老师""值班人员"）；去除电话号码 |
| c | 合成文本 | 仅用于放量（见 2.3 比例与 §8 偏差登记 D-2）；构造规则见 §2.5 |

### 2.3 各档真实/合成比例（Human 2026-08-31 指令：允许合成，须比例声明）

- 200 档：真实（a/b 档）≥ 80%，合成 ≤ 20%；
- 1000 档：真实 ≥ 60%，合成 ≤ 40%；
- 5000 档：真实 ≥ 40%，合成 ≤ 60%。
- 下限为最低要求；实际可得真实语料多于下限时优先真实。各档**实际构成比例**由 M6.2 在 §5 登记原始数字。
- **质量门锚定规则**：30 条金标查询的 `expected_pages` 一律锚定真实来源页（a/b 档）或按 §3.1 锚点规格以真实通知语体撰写的锚点页；合成文本仅承担放量与干扰角色，**不得进入任何金标 `expected_pages`**。若 M6.2 实操中真实来源不足以支撑个别锚点页，回退＝该锚点页降为合成 ＋ §8 逐条登记（引用同一 Human 授权）。

### 2.4 仓库已有真实中文内容盘点（本批完成）

| 项 | 结论 |
| --- | --- |
| fixtures / 种子数据目录 | 无（`find` 零命中） |
| `tests/` 中文内容 | 约 30 个测试文件含中文片段（单文件含中文行 90–160 行），均为短标题/断言文案，**非通知语体正文**，独立中文短语量级 ＜200 个 |
| `docs/` 中文 | 治理文档（计划/契约/ADR），非校园语料，不适用 |
| 结论 | 仓库可得真实校园语料 ≈ 0，不足以支撑 200 档；**主路径＝b 档采集 ＋ a 档请领，c 档合成放量**，比例按 §2.3 |

### 2.5 合成文本构造规则（c 档）

- 基于真实校园信息语言分布：句式、事务词汇、板块/部门/标签分布从 b 档已采语料统计导出（词频与篇长分布随 §5 留档）。
- 事件、日期、数量、地点组合为**虚构**，不复制任何真实公告全文段落——既满足"基于真实语言分布"，也不伪装成真实学校公告。
- 词汇覆盖五大板块（IA §2 冻结 slug）：`chronicle`（校园纪事/通知文章）、`events`（校园活动）、`materials`（学习资料）、`software`（软件与工具）、`guide`（校园指南）。
- 指南类锚点页允许 FAQ 问答体（"问：……？答：……"）——真实校园指南常见文体，用于承载 §3 长句条目的问句原文。

### 2.6 隐私规则（PRD §11 禁敏感数据句、§12 隐私条款逐句对照）

- 零个人隐私：不出现真实人名、工号、学号、电话、身份证号、成绩；a/b 档源文本含之则按 §2.2 脱敏。
- 站内不得发布的保密材料类内容不进入数据集（PRD §12"不发布个人敏感信息或面向内部的保密材料"）。
- 软件板块不收录破解版软件条目（PRD §11"未获校方明确批准前不得加入"）。

### 2.7 禁止占位语料

"测试文章001"/Lorem ipsum/随机无意义汉字/重复模板仅改数字类语料**不得作为主要实验数据**（契约 §2）。合成文本以 §2.5 规则产出真实感条目，M6.2 构造脚本中占位样式字面量出现即构造失败（构造期断言）。

### 2.8 字段契约（CONTENT_MODEL §23.1 五字段，字段名严格一致）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | CharField | 标题 |
| `body` | 纯文本长字段 | 正文文本（StreamField 纯文本化；指南类＝结构化字段拼接） |
| `department` | CharField 代号 | `Department.slug`（与 IA §4.1 同源） |
| `tags` | CharField 逗号分隔 | `Tag.name` 串（仅 N/A/M 三类型携带） |
| `category` | CharField | 受控类别词表 name（M＝discipline/material_type；G＝category；S＝platforms；N/A＝空） |

- 数据集存储形态：JSONL（每行一页对象，首字段为稳定页标识 `page_id`，§3.1）。
- 分布要求（02 S6.1 §2）：**≥5 个部门代号、全部五板块、≥20 个标签**。
- 部门代号集（8 个，虚构，`is_active=True` 语义）：`jwc`（教务处）、`xgb`（学工部）、`xsc`（学生处）、`tsg`（图书馆）、`cwc`（财务处）、`cpc`（信息中心）、`tw`（校团委）、`rsc`（人事处）。
- 标签词表（22 个）：学术讲座、就业招聘、奖助学金、评奖评优、考试安排、选课指南、宿舍生活、安全教育、社团活动、志愿服务、图书馆资源、自习空间、校园卡、网络服务、实习实践、竞赛信息、出国交流、心理健康、体育赛事、文艺演出、报销指南、设备借用。

### 2.9 构造期校验（使 hit@10 第三方可复算的数据集侧义务；M6.2 自动执行，本批冻结规则）

每档数据集构造完成后、实验开始前，执行以下校验，任一失败＝该档数据集无效，须返工：

1. **负例校验（A 档条目）**：对标注「A档」的金标条目，以 E1 最宽语义（完整查询串 `icontains`）全库扫描：串出现页集合 ＝ 该条 `expected_pages`（无结果条目＝空集）。
2. **锚点可达校验（全部条目，含 B 档）**：分别以 E1/E2/E3 三种匹配语义模拟执行每条金标查询（`order_by_relevance=False`，默认排序 `-first_published_at`），校验 `expected_pages` 全部落入 top10。不满足时调整锚点页 `first_published_at`（锚点页区间＝语料时间轴上最新 10% 时间跨度带宽内的页面，时间戳唯一）直至通过；无法通过＝数据集构造失败。
3. **分布校验**：部门代号 ≥5、板块＝5/5、标签 ≥20、五字段非空率 100%。
4. **占位校验**：§2.7 禁止样式字面量零命中。
5. **比例校验**：各档真实/合成比例满足 §2.3 下限。

## 3. 查询集（金标集，30 条固定表格）

### 3.1 稳定页标识与锚点页方案（CONTENT_MODEL §23.2 授权 M6.1 定）

- 数据集每行首字段 **`page_id`**＝`P`＋三位序号（`P001`…`P5000`），全档间稳定（同一 `page_id` 跨 200/1000/5000 档指向同一页）。
- **锚点页**＝金标查询的目标页，固定占用 `P001`–`P044` 区间，随本报告冻结（下表 `expected_pages` 即其 `page_id`）；M6.2 构造时按锚点规格植入：锚点页以真实通知语体撰写，标题/正文/结构化字段包含使对应查询确定命中的文本（FAQ 体见 §2.5），部门/标签/板块按表列取值。

- `required_filters` 语法＝CONTENT_MODEL §21.1 参数集（`section`/`dept`/`type`/`tag` 四参；`q` 单列表列；空对象＝纯 q 条）；取值域对齐 §2.8 部门代号与 IA §2 板块 slug、§2.8 标签词表。
- 负例档位标注：**A档**＝§2.9-1 严格负例；**B档**＝通用高频词，负例豁免，仅受 §2.9-2 锚点可达校验约束。

## 4. 评分口径与达标阈值（先验冻结，不得实验后修改）

### 4.1 质量门：hit@10 ≥ 90%

**精确定义**：

- 对金标条目 q：以 §4.4 执行口径运行查询，取得结果列表前 10 条（top10；结果不足 10 条则取全部）。
- **hit@10(q) ＝ 1 当且仅当 `expected_pages` ⊆ top10 的 `page_id` 集合**；否则 0。
- **无结果条目（`expected_pages`＝∅，Q21/Q29）**：hit@10(q) ＝ 1 当且仅当**结果集为空**；非空即 0。
- **hit@10（方案 × 档位）＝ 30 条 hit@10(q) 的算术平均**；达标 ⇔ hit@10 ≥ 90%（即 ≥ 27/30 条）。
- 质量门判定档位＝**200 与 1000 档**（两档均须达标）；5000 档 hit@10 照测照记，作观察项（合成占比高，不作门——对齐 02 S6.1"合成文本放量、不参与质量评分"的档位语义，见 §8 D-2）。

**逐条判定步骤（第三方可复算）**：

1. 装载该档数据集（JSONL，§2.8），执行 `update_index`（E1 为 SQLite 后端同操作）。
2. 对每条金标：组装 queryset＝按 `required_filters` 施加 §21.1–§21.2 维度过滤＋可见性谓词（`live ∧ ¬expired`，§21.5），再 `.search(query, order_by_relevance=False)`；结果按 `-first_published_at` 排序（E1 天然 queryset 序）。
3. 取 top10 的 `page_id` 集；按上述定义记 hit@10(q)∈{0,1}；逐条记录进结果表（30 行 × 方案 × 档位）。
4. 复算前提：数据集已通过 §2.9 全部构造校验（负例/锚点可达/分布/占位/比例）；复算方可用任一独立脚本，判定结果与 §5 原始表不一致时以重跑为准并报偏差。

### 4.2 性能门：1000 档 p50 < 1s

- **计时对象**＝服务端单次 `.search()` 调用墙钟时间（`time.perf_counter` 差值；含 queryset 组合与后端执行，不含 HTTP/中间件/模板渲染——M7.2 端到端口径另测，此处为 S6.1 查询计时口径）。
- **计时程序**＝`update_index` 完成后开始；每条金标查询**预热 1 次（不计时）→ 正式执行 20 次计时**；同机、同数据、同查询集、同一计时脚本；三方案串行，实验期间无并行重负载。
- **p50**＝20 次样本的中位数（升序第 10、11 位的均值）；**p95**＝升序第 19 位值（ceil(0.95×20)）——定义固定，避免实现歧义。
- **达标判据（最严口径，先验冻结）**＝该方案在 **1000 档**的 30 条查询**逐条 p50 全部 < 1s**（对齐 PRD §14"普通搜索请求约 1 秒内返回"）；200/5000 档 p50/p95 照测照记作观察项。方案级汇总记录：30 条 p50 的中位数、逐条 p95 的最大值。
- 计时环境登记（M6.2 §5 填写）：机型/CPU/内存/PG 与 SQLite 版本/容器配置/日期。

### 4.4 决策规则（先验冻结）

按以下顺序**机械推导**，不引入任何实验外判断：

1. E1 达标（§4.1＋§4.2 两门同过）→ **选 E1**（最简单优先）；
2. E1 不达标、E2 达标 → **选 E2**；
3. E1/E2 均不达标、E3 达标（E3 可装且跑通全部档位）→ **选 E3**；
4. 三者均不达标，**或 E3 环境不可行（ENVIRONMENT_INFEASIBLE，§1.3）且 E1/E2 均不达标** → 结论 **`INDEPENDENT_SEARCH_SERVICE_EVALUATION_REQUIRED`**，升级项目负责人裁决（PRD §10 决策门 4："首版优先评估 PostgreSQL 与 Wagtail 自带搜索能力；只有验证不达标时才评估独立搜索服务"）；**禁止自动安装任何独立搜索服务**（Elasticsearch/OpenSearch 类仅为结论标签，非候选执行项）。

本规则对 02 S6.1 §4 决策规则逐句忠实（含"最简单优先"次序与 D7 升级路径），无改动。
