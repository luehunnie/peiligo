## 1. 站点树总图

### 1.1 四层树形结构

站点树固定四层（02 S2.1 §1）：**首页（第 1 层）→ 五个一级板块页（第 2 层）→ 部门容器节点（第 3 层）→ 内容页（第 4 层）**。V1 不允许其他层级形态；扩层须走变更流程（00 §3 修订清单纪律），不得在实现步骤内静默扩围。

```text
站点根（Wagtail Root，不计数）
└── 首页 HomePage（/，第 1 层，全站唯一）
    ├── 校园纪事 SectionPage（/chronicle/，第 2 层）
    │   └── 部门容器 DepartmentContainerPage（/chronicle/<dept>/，第 3 层，前台 404）
    │       └── 内容页（/chronicle/<dept>/<slug>/，第 4 层：通知页 / 文章页）
    ├── 校园活动 SectionPage（/events/）
    │   └── 部门容器（/events/<dept>/，前台 404）
    │       └── 内容页（/events/<dept>/<slug>/：通知页 / 文章页；活动内容经结构化字段承载，见 §5）
    ├── 学习资料 SectionPage（/materials/）
    │   └── 部门容器（/materials/<dept>/，前台 404）
    │       └── 内容页（/materials/<dept>/<slug>/：学习资料条目页）
    ├── 软件与工具 SectionPage（/software/）
    │   └── 部门容器（/software/<dept>/，前台 404）
    │       └── 内容页（/software/<dept>/<slug>/：软件与工具条目页）
    └── 校园指南 SectionPage（/guide/）
        └── 部门容器（/guide/<dept>/，前台 404）
            └── 内容页（/guide/<dept>/<slug>/：校园指南条目页）
```

### 1.2 示例路径

| 层级 | 节点（示例） | URL | 前台状态 |
| --- | --- | --- | --- |
| 1 首页 | HomePage | `/` | 200 |
| 2 板块页 | 校园纪事 | `/chronicle/` | 200 |
| 3 部门容器 | 例：教务处容器 | `/chronicle/jwc/` | **404（或等效不可达，§3.2）** |
| 4 内容页 | 例：教务处发布的通知 | `/chronicle/jwc/2026-autumn-course-notice/` | 200 |

示例部门 slug `jwc` 仅为示意；实际部门清单由 Department Snippet 数据承载、总管理员维护（ADR-0005 载体表 #7，见 §3.4）。

### 1.3 建容器规则

- **仅为确有内容的部门建容器**（ADR-0004"代价与权衡"遗留的建容器规则，在此落定）：某板块下某部门尚无内容时不预建容器；部门内容清空后容器可保留（保持权限锚点稳定）或由总管理员清理，两种处置均不影响前台（容器本就 404）。
- 部门容器只挂在板块页下（不挂首页、不挂根、不嵌套容器）；内容页以本部门容器为唯一父级（ADR-0004 决策 1）。
- 首页一个、板块页五个，均全站唯一；不设五个一级板块之外的任何一级节点（PRD §6）。

## 2. 五板块定义

板块中文名**冻结，与 PRD §6 一字不差**：校园纪事 / 校园活动 / 学习资料 / 软件与工具 / 校园指南。旧站 3 个不一致命名——**院内逸事、软件资源、学院指南——一律弃用**，不得复入任何界面、URL、代码标识或文案（旧站审计 R12：`content-types.ts:14-36` vs PRD:97-101；02 §0.2-7）。

| # | 中文名（冻结） | slug（默认，B 阶段可微调） | 一句话定位 | 承载内容（PRD §7） |
| --- | --- | --- | --- | --- |
| 1 | 校园纪事 | `chronicle` | 记录校园动态、通知公告与长期报道的板块 | 通知（PRD §7.1）、文章（PRD §7.2） |
| 2 | 校园活动 | `events` | 发布校园活动预告、进行中与回顾信息的板块 | 通知、文章、活动结构化字段（PRD §7.3，经 Notice/Article Page 承载，§5） |
| 3 | 学习资料 | `materials` | 按学科/专业方向与资料类型组织的学习资源共享板块 | 学习资料条目（PRD §7.4） |
| 4 | 软件与工具 | `software` | 汇集校园常用软件与在线工具入口及使用说明的板块 | 软件与工具条目（PRD §7.5，外链经统一确认跳转页） |
| 5 | 校园指南 | `guide` | 面向全校的生活与办事固定信息板块 | 校园指南条目（PRD §7.6） |

一句话定位为本文的归纳表述，语义引源 PRD §7 各节；板块中文名的唯一权威为 PRD §6。板块描述"信息是什么"，部门字段描述"谁发布"（PRD §6 原文）——板块是内容维度的第一级划分；部门不是板块、不构成导航层级（见 §3）。

## 3. 部门容器树规则

### 3.1 结构：权限挂载点 + 路由分组

每个板块页下按部门建立容器节点（工作名 DepartmentContainerPage）：

- **容器 = 权限挂载点**：页面树权限（Add/Edit/Publish/Lock/Unlock）挂在各部门容器节点上并向子树传播；部门内容页以本部门容器为唯一父级，部门隔离由树形权限传播天然成立，不自写权限逻辑（ADR-0004 决策 1）。
- **容器 = 路由分组**：URL 中的部门段由容器节点在树中的位置派生（§4 方案 A）；容器节点本身不承载任何内容字段，不是内容页。

### 3.2 前台 404 / 等效不可达（硬约束）

容器节点不构成前台部门主页（ADR-0004 标题与决策 2；02 §0.2-3）：

1. 前台访问容器节点 URL 返回 **404（或等效不可达）**；
2. **不进入导航**、**站点地图（sitemap.xml）**、**默认列表**与**默认搜索结果**；
3. URL 可含部门段，但该 URL **不渲染任何部门聚合页**。

落实位点分工：本节冻结语义；导航/sitemap/默认搜索排除的实现与 noindex 位点由 M2.2 §6/§10 细化；404 与四类排除的实测由 M4.2 原型与 M4.3 越权矩阵验证（ADR-0004"验证证据"节回写）。

### 3.3 部门字段的唯一合法用途：元数据 + 筛选维度

PRD §6 原文（逐句对照）：

> 板块描述"信息是什么"，部门字段描述"谁发布"。任何部门均不建立独立主页。
>
> 部门名称作为内容作者元数据展示，并可用于搜索结果筛选；部门筛选结果不是部门主页。

由此：

- 部门名称在内容页作为**作者元数据**展示（PRD §4.3：前台只显示部门/单位名称，不显示登录用户名或具体操作人员姓名）；
- 部门作为**搜索/筛选维度**（PRD §10：站内搜索至少覆盖发布部门）；
- **部门筛选结果不是部门主页**：筛选结果是"按部门维度过滤后的内容列表"，不是某部门的门户页。其 URL 形态、标题文案（"XX 部门发布的内容（筛选结果）"类）与无结果空态由 M2.2 §8/§9 定义；本步冻结语义——任何筛选结果页不得呈现为部门"主页/门户"形态；
- **无部门主页是 V1 硬约束**：PRD §20 V1 不做清单含"部门独立主页"；本架构不提供任何部门聚合页、部门简介页或其他部门主页形态的页面（02 §0.2-3/§0.2-5）。

### 3.4 部门数据来源

部门清单与部门 slug 由 Department Snippet 承载（ADR-0005 载体表 #7：内部治理对象，无公开独立 URL，前台只展示部门名称）；V1 部门账号不持有任何 Snippet 权限，词表/部门数据均由总管理员管理（ADR-0004 决策 3）。

## 4. URL 方案

### 4.1 选定方案（方案 A，默认）：URL 含部门段

内容页 URL 形态：`/<板块 slug>/<部门 slug>/<内容 slug>/`

- 示例：`/chronicle/jwc/2026-autumn-course-notice/`；
- 容器段 `/<板块>/<部门>/` **不渲染任何页面**：GET 返回 404（§3.2）；
- 板块页 URL：`/<板块 slug>/`（如 `/chronicle/`）；首页 URL：`/`。

**选定理由**：

1. **零 URL 生成覆写**：Wagtail 的 URL 由页面树路径原生派生，方案 A 无需覆写路由/URL 生成机制，不改核心（02 §0.2-2）；
2. **权限边界与 URL 结构同构**：树径 = URL 径，后台浏览结构、权限边界与前台地址一致，部门编辑心智模型简单（ADR-0004"正面收益"）；
3. **与 ADR-0004 决策 2 完全相容**："URL 方案可含部门段，但该 URL 不渲染任何部门聚合页"——方案 A 正是该表述的直接落实；
4. 已知短板与接受理由：URL 含部门段意味着内容换部门归属需移动页面（URL 随之变化）——部门归属变更本属治理操作，且 Wagtail 移动页面可自动生成重定向（redirects 贡献位由 M2.2 §10 核对）。

### 4.2 否决候选（方案 B，记录）：无部门段

形态：`/<板块 slug>/<内容 slug>/`（如 `/chronicle/2026-autumn-course-notice/`）。

- 描述：URL 隐去容器层，内容页地址直接挂在板块段下；
- 否决理由：需覆写 Wagtail 的 URL 生成/路由派生（树径 ≠ URL 径），复杂度高；后台树形浏览与前台 URL 心智模型分裂；权限树结构不变而 URL 层额外失配，徒增实现与测试面；
- 处置：记录为否决候选。若后续版本确需短 URL，须新开 ADR 重开（沿 ADR-0005"硬规则"的变更纪律），不得在实现步骤内静默改判。

### 4.3 slug 规范（默认值，B 阶段可微调并留痕）

| 项 | 规则 |
| --- | --- |
| 字符集 | ASCII 小写字母、数字、连字符（`[a-z0-9-]`）；不得含中文、大写、下划线、空格 |
| 来源 | 中文词转 ASCII 拼音（全拼或约定缩写）或英文 |
| 唯一性 | 同一父节点内唯一（Wagtail slug 原生约束） |
| 长度 | 建议 ≤ 64 字符 |
| 板块 slug | `chronicle` / `events` / `materials` / `software` / `guide`（§2 表，默认值） |
| 部门 slug | Department Snippet 字段，总管理员维护，创建后原则上不变更 |
| 尾斜杠 | 规范形带尾斜杠（Django `APPEND_SLASH` 默认行为） |

### 4.4 URL 一览

| 页面 | URL | 前台状态 |
| --- | --- | --- |
| 首页 | `/` | 200 |
| 板块页（×5） | `/chronicle/`、`/events/`、`/materials/`、`/software/`、`/guide/` | 200 |

## 6. 全局导航与面包屑

### 6.1 全局导航结构（写死）

全局导航分页头与页脚两区，全站页面统一渲染（ADR-0002 服务端模板；实现位=MB9 全局模板，本节冻结结构与排除规则，不冻结视觉）：

| 区位 | 构成（固定） | 说明 |
| --- | --- | --- |
| 页头 | 品牌区（站名，链至首页 `/`）+一级导航：**首页+五板块**（顺序按 §2 表 #1–#5：校园纪事、校园活动、学习资料、软件与工具、校园指南）+站内搜索入口（指向 `/search/`，§9） | 一级导航项**仅此七类**；当前板块项以 `aria-current` 高亮（PRD §13 无障碍；头部结构沿旧站骨架，旧站审计 §5.2 SiteHeader 行） |
| 页脚 | **关于**（站点说明）+**反馈**（统一工作邮箱） | 均为工具入口，**不构成一级板块、不新增任何页面树节点**（§1.3；PRD §6） |

- **反馈**：每页页脚提供统一工作邮箱链接（PRD §8：学生发现内容错误、链接失效或侵权问题时反馈），邮件链接自动带上内容标题与页面地址（PRD §8）；邮箱取值存站点级配置（ADR-0005 载体表 #14"统一反馈邮箱"）。
- **关于**：V1 以页脚静态说明文案承载（站点性质与免责口径），**不建独立"关于"页面**——新增任何树节点即违反 §1.1 四层冻结形态，B 阶段如需独立页面须走变更流程（00 §3 修订清单纪律）；文案与免责结构沿旧站页脚骨架重写（旧站审计 §5.2 SiteFooter 行：陈旧"M1 原型"文案必须重写，不得沿用）。
- 投稿/反馈措辞口径：旧站"向项目方投稿"页面文案弃用，统一改为"纠错/失效链接/版权反馈至统一工作邮箱"（旧站审计 §5.2 投稿说明行；PRD §4.1/§8）。

### 6.2 导航、默认列表与默认搜索的排除规则（承接 §3.2，不重定义 404 语义）

§3.2 冻结容器"不进入导航、sitemap、默认列表与默认搜索"；本节落定排除的**实现位点**（容器 404/等效不可达语义以 §3 为准）：

| 排除对象 | 位点 | 规则 |
| --- | --- | --- |
| 全局导航 | §6.1 导航数据源 | 一级导航为固定清单（首页+五板块+搜索入口），**永不查询、永不渲染部门容器**；全站模板不生成任何指向 `/<板块>/<部门>/` 的链接 |
| 板块默认列表 | 板块页无参数态（§9） | 列表仅列本板块内容页（第 4 层叶子），容器不是列表项、无列表标题 |
| 默认搜索 | 搜索索引（M3.4 契约承接） | 索引与默认结果不含容器类型——容器前台 404，本就不具可索引内容（IA-04 验证位点即本节） |
| Snippet/设置对象 | 前台路由之外 | 无公开独立 URL，天然不进任何导航/列表/搜索（ADR-0005 载体表 #7–#14） |

### 6.3 面包屑规则（按 §4 方案 A 写死）

| 页面 | 面包屑 | 示例 |
| --- | --- | --- |
| 首页 | 无面包屑 | — |
| 板块页 | 首页 > 板块名 | 首页 > 校园纪事 |
| 内容页 | 首页 > 板块名 > 内容标题 | 首页 > 校园纪事 > 2026 秋季选课通知 |
| 全站搜索页 | 首页 > 站内搜索 | 筛选/搜索态的标题随参数变化（§8.2） |

- **路径含板块、不含容器段**：部门容器不出现在任何面包屑中（可点链接与纯文本均不出现）。
- 写死理由：① 容器前台 404（§3.2），不可作为可点面包屑链接；② 部门不是板块、不构成导航层级（PRD §6；§2 尾注）；③ 部门归属以**作者元数据**在内容页展示（§3.3；PRD §4.3），不经路径层级表达。内容页信息结构沿旧站"面包屑→标题→meta→摘要→正文→补充信息→来源"骨架（旧站审计 §5.2），部门名位于 meta 区而非路径区。
- 除最后一段（当前页，纯文本）外，每一段均为可点链接且指向 §4.4 表中的 200 URL；面包屑**不含任何 404 目标**。

> 本节断言：IA-06（导航与默认列表不含容器入口）、IA-07（面包屑一致性），见附录 §13。

## 7. 首页信息优先级（PRD §9 逐层对应）

### 7.1 四层优先级与展示位点（写死）

首页区块**自上而下的排布顺序 = 信息优先级顺序**，与 PRD §9 四层逐层对应：

| 顺序 | 区块 | 内容来源 | 展示位点 |
| --- | --- | --- | --- |
| 1 | **紧急或重要提示** | 站点级配置（ADR-0005 载体表 #14"紧急提示"），仅总管理员维护 | 首页顶部全宽提示条；无内容时整条不渲染（不留空壳） |
| — | **推荐位/置顶位**（运营区块，见 §7.2；不占用四层序号） | FeaturedItem Snippet（ADR-0005 载体表 #13） | 紧急提示之下、最新通知之上；空缺时区块整体不渲染 |
| 2 | **最新且仍有效的通知** | 自动列表：全站通知按发布时间倒序（PRD §7.1），**仅含未过期**——到期自动退出首页与默认列表，保留历史归档与站内搜索（PRD §7.1） | 通知列表区 |
| 3 | **近期校园活动** | 自动列表：校园活动板块内容按活动时间邻近排列（活动结构化字段承载，§5；字段终判 M3.1/M3.2） | 活动列表区 |
| 4 | **五个一级板块入口与其他内容** | §2 五板块固定入口网格+其他（站内搜索入口、页脚关于/反馈） | 板块入口网格区 |

首页主体自动展示最新内容，不依赖人工维护（PRD §9）；各自动列表的条数为展示参数，默认值由实现阶段（MB9）定，不属本架构冻结项。

### 7.2 推荐位与置顶位规则（数量固定原则）

- **载体**：FeaturedItem Snippet，含起止时间（ADR-0005 载体表 #13：起止时间控制展示窗口，窗口外自动下线；实现位=MB8）。
- **管理权**：仅总管理员（PRD §8：只有总管理员可以设置全站重要内容或首页置顶；**部门如需置顶，通过统一工作邮箱申请**——不开放部门侧自助置顶）。
- **数量固定**：推荐位**槽位总数为固定常量**（站点级配置设定后保持固定），**不随内容量或申请量自动增长**；超出槽位的申请一律不展示。V1 默认槽位数已经 Human 确认（2026-08-31，Q14）＝**最多同时生效 3 条**（见下注）；实现阶段在配置中给定并留痕。
  - **Human 确认（2026-08-31，G2-A Q14/Q15）**：首页人工推荐内容**最多同时生效 3 条**（0 条时推荐区可以隐藏；不足 3 条按实际数量展示）；推荐内容**默认有效期 30 天**，管理员可以提前撤下或延长。决策台账＝`docs/G2_HUMAN_DECISIONS.md` Q14/Q15。
- **语义区分**：**置顶**=将某内容在其所属优先层列表内置于首位（有起止时间，到期回退自动排序）；**推荐**=在 §7.1 独立运营区块展示。两者均**不改变 §7.1 四层顺序本身**。

> 本节断言：IA-13，见附录 §13。

## 8. 部门筛选语义（筛选结果页 ≠ 部门主页）

### 8.1 语义冻结与 PRD §6 原文

PRD §6 原文（逐句对照）：

> 板块描述"信息是什么"，部门字段描述"谁发布"。任何部门均不建立独立主页。
>
> 部门名称作为内容作者元数据展示，并可用于搜索结果筛选；部门筛选结果不是部门主页。

部门筛选是**搜索/列表的过滤维度**（§3.3），不是一种页面形态：筛选结果=既有 200 页面（板块列表页、全站搜索页）在 query 参数下的**动态过滤状态**（URL 形态见 §9），**不存在任何承载它的独立页面树节点**——不新增 URL 路径、不进页面树、不设固定导航入口。容器段 `/<板块>/<部门>/` 仍按 §3.2 返回 404，筛选结果永不落在该路径上。

### 8.2 标题文案规则（写死）

| 载体页面 | 页面主标题（H1）与 `<title>` 模式 |
| --- | --- |
| 板块页+`?dept=` | `<板块名>·<部门名>发布的内容（筛选结果）`（例：校园纪事·教务处发布的内容（筛选结果）） |
| 全站搜索页+`?dept=` | `站内搜索·<部门名>发布的内容（筛选结果）` |

- 标题**必须**含"（筛选结果）"后缀，明示这是过滤视图而非部门页面；
- **禁用措辞清单**：`XX 部门主页`、`XX 部门门户`、`XX 部门空间`、`XX 部门专区`、`进入 XX 部门`等一切门户化措辞（IA-08：筛选页 title 不含"主页"字样）；
- 部门名称同时在每条结果条目上以**作者元数据**展示（§3.3；PRD §4.3：只显示部门/单位名称，不显示登录用户名或操作人员姓名）。

### 8.3 筛选结果页 vs 部门主页：显式禁令对照表

> "无部门主页"是 V1 硬约束（PRD §6 原文、PRD §20 不做清单、§3.3）。下表把**允许的筛选结果页**与**禁止的部门主页形态**逐维对照，供实现与审查双向核对（右列任一形态出现即违规）：

| 维度 | 筛选结果页（允许，唯一合法形态） | 部门主页（**禁止**） |
| --- | --- | --- |
| URL | 既有页面+query 参数（§9）：`/chronicle/?dept=jwc`、`/search/?dept=jwc` | 固定路径承载部门聚合——`/chronicle/jwc/` 必须维持 404（§3.2/§4.4），不得为其渲染任何页面 |
| 页面性质 | 参数过滤下的内容列表；去掉参数即回退普通列表/搜索页 | 门户页：部门简介、横幅、定制栏目、部门策展 |
| 标题文案 | 含"（筛选结果）"（§8.2） | "XX 部门主页/门户/空间"类措辞 |
| 内容组成 | 该部门在对应范围内的全部内容，按时间倒序等中立排序 | 部门自我介绍、部门联系方式、部门专属推荐位 |
| 导航地位 | 无固定导航入口；到达路径=用户主动筛选或分享链接 | 出现在全局导航/默认列表/默认搜索（违反 §6.2） |
| 收录 | noindex（§10 #6/#7） | ——（不存在，无从收录） |
| 权限语义 | 无（纯前台过滤，不涉权限） | 把后台权限容器（§3.1）前台化为"部门空间" |

### 8.4 部门筛选无结果空态

部门筛选无结果时呈现"筛选无匹配"空态，保留筛选条件展示并提供"清除筛选"动作（§11 四态规格）；空态文案同样受 §8.2 禁用措辞清单约束。

> 本节断言：IA-08（+交互规格断言 IA-11/IA-12 见 §9/§10），见附录 §13。

## 9. 搜索与筛选 URL 状态规格（移植旧站规格并中文化）

> 交互规格源：旧站审计 §5.1"URL 驱动的搜索/筛选状态（`?q=&type=`，非法值回退全部）——可分享、可刷新、面包屑可复原"（`ContentListPage.vue:66-89,116-139`；`ContentCard.vue:13-21`）。本节将其移植为 V1 全量参数规格（中文化、扩维至五参数），供 M3.4（筛选维度契约）与 MB10（搜索视图实现）直接消费。

### 9.1 载体页面与参数集

| 载体 | URL 形态 | 生效参数 |
| --- | --- | --- |
| 全站搜索页（自定义视图，不入页面树；载体先例=外链确认跳转页，ADR-0005 载体表 #5；`/search/` 为 V1 默认路径，B 阶段可微调并留痕；实现位=MB10） | `/search/?q=&section=&dept=&type=&tag=` | 全部五参数 |
| 板块列表页（页面树节点，§4） | `/<板块>/?q=&dept=&type=&tag=` | 四参数；**板块维度由路径唯一决定**——`?section=` 仅在 `/search/` 生效，板块页上一律忽略 |

| 参数 | 语义 | 取值 | 非法处置 |
| --- | --- | --- | --- |
| `q` | 关键词，覆盖标题与正文等（PRD §10 搜索覆盖面：标题/正文/板块/内容类型/部门/受控类别和标签/校园指南结构化信息——索引字段映射由 M3.4 契约承接；**不做前端过滤**，ADR-0002 否决理由） | 任意词串，服务端搜索 | 空串=不加条件 |

### 9.2 状态语义（写死）

1. **全参数可选**：不携带任何参数=无过滤的全部内容（`/search/` 无参数=搜索表单态）；
2. **非法值回退全部**：未知 slug、空值或格式非法的参数值**视同未提供该参数**，页面照常 200 渲染——**不 404、不 5xx、不渲染错误页**；
3. **可分享、可刷新、可复原**：全部状态只存在于 URL（GET），服务端渲染直接呈现结果（ADR-0002，无 JS 依赖）；从列表进入详情后返回，筛选状态经 URL 原样复原（旧站"携带 q/type 进详情"规格的移植：详情页"返回列表"链接带回原 query 参数）；
4. **排序默认中立**：默认按发布时间倒序（PRD §7.1 口径），施加筛选不改变排序规则；
5. 分页等其余参数不属本步冻结项，实现时遵循同一"URL 承载全部状态"原则（MB10）。

部门筛选态的标题文案与禁令见 §8；筛选态的收录处置见 §10。

## 10. SEO/noindex 位点清单

PRD §12 口径：学生前台公网公开访问、无需登录；**默认允许搜索引擎收录，单篇内容可设置 `noindex`**；站内不发布个人敏感信息或内部保密材料。据此全站位点清单如下（逐条挂断言）：

| # | 页面/状态 | URL | robots（meta） | sitemap.xml | 断言 |
| --- | --- | --- | --- | --- | --- |
| 1 | 首页 | `/` | 默认可收录（index） | 收录 | IA-10 |
| 2 | 板块页 ×5 | `/<板块>/` | 默认可收录 | 收录 | IA-10 |
| 3 | 内容页（默认态） | `/<板块>/<部门>/<slug>/` | 默认可收录 | 收录 | IA-10 |
| 4 | 内容页（单篇 noindex 态） | 同上 | **noindex**（单篇字段置位时） | **同步退出**（不向搜索引擎发送矛盾信号） | IA-09 |
| 5 | 部门容器 | `/<板块>/<部门>/` | ——（前台 404，无页面可收录） | **排除**（IA-03 位点即本行） | IA-02/IA-03 |
| 6 | 板块筛选态（含 query 参数） | `/<板块>/?…` | **noindex** | 排除 | IA-12 |
| 7 | 全站搜索页（含无参数态） | `/search/` | **noindex** | 排除 | IA-12 |
| 8 | 外链确认跳转页（自定义视图） | 跳转视图 URL（ADR-0005 载体表 #5） | **noindex** | 排除 | IA-12 |

### 10.1 noindex 实现位点

- **单篇 noindex**（#4）：内容页模型布尔字段，编辑位=后台 promote 侧；输出位=全局模板 `<meta name="robots">`（ADR-0002 决策 2：meta/noindex 由模板与页面机制直接控制）。字段正式定义由 M3.2 字段表终判，本节冻结语义与位点；实现位=MB13。
- **筛选态/搜索页/跳转页 noindex+canonical**（#6–#8）：全部 query 状态页输出 noindex，并输出 `<link rel="canonical">` 指向**去除全部 query 参数**的基础 URL（对应板块页/`/search/`）——参数组合无限，任一参数态不构成独立收录单元（**筛选结果页 noindex 策略**：覆盖 §8 全部筛选态，与容器排除（#5）共同构成"部门维度永不产生可收录页面"的闭环）。
- **sitemap 贡献位**：仅 #1–#3（未置 noindex 的 200 页面树节点）进入 sitemap.xml；生成机制由 MB13 实现，本节冻结贡献范围。
- **robots.txt**：V1 不依赖 robots.txt 做内容管理（容器 404 与 noindex 已覆盖 #4–#8），不新增 robots.txt 层面的排除规则。

### 10.2 redirects 贡献位核对（兑现 §4.1 预留）

§4.1 预留"页面移动自动重定向（redirects 贡献位）由 M2.2 §10 核对"。核对结论：**V1 依赖 Wagtail 原生机制即可，不自建重定向体系**——① 页面在树内移动（含内容换部门归属导致的容器间移动，§4.1 已知短板场景）时原生自动生成重定向；② 板块 slug B 阶段微调等场景由总管理员以后台原生 redirects 手工增补。两者均无需自定义代码，与方案 A 相容；实现核对位=MB13。

### 10.3 分析位点注记

PRD §12 要求收集匿名且最小化的页面访问、搜索词、**无结果搜索**与**筛选使用**数据：收录策略不影响前端匿名统计；"无结果搜索/筛选使用"埋点与 §11"筛选无匹配"空态一一对应。数据收集项与隐私口径的正式规格属 M7.2（非功能基线，输入含本步），本节仅登记对应关系。

> 本节断言：IA-09、IA-10、IA-12（容器排除另见既有 IA-02/IA-03），见附录 §13。

## 11. 无结果/空态规格（四态）

> 规格源：旧站审计 §5.1"列表页四态交互规格（loading / error+重试 / 全空 / 筛选无匹配）——作为验收级交互规格文档复用（PRD §10 要求'清晰的无结果提示'）"（`ContentListPage.vue:174-220`、`ContentDetailPage.vue:104-131`）。本节中文化落定并绑定载体。

| 态 | 触发 | 文案要点（中文） | 落点 |
| --- | --- | --- | --- |
| 载入中 | 列表请求进行时 | "正在加载……"+占位/骨架样式 | 板块页、`/search/`、各筛选态 |
| 出错+重试 | 请求失败 | "加载失败，请重试"+**重试按钮**；不静默回退假数据（沿旧站错误语义，旧站审计 §5.2 API 错误三分行） | 同上；内容详情页同规则 |
| 全空 | 范围内无任何内容（无筛选参数） | "本板块暂无内容"+引导至其他板块/首页入口 | 板块页无参数态 |
| 筛选无匹配 | 携带筛选/搜索参数且结果为 0 | "没有符合当前条件的内容"+**清除筛选**动作（回退全部，§9.2）+已选条件回显 | `/search/`、板块筛选态（含部门筛选，§8.4） |

- **全空 ≠ 筛选无匹配**：前者是范围本身为空，后者归因于当前参数——两态的文案与动作必须区分，不得以同一句"暂无内容"混用；
- 部门筛选无匹配文案同受 §8.2 禁用措辞清单约束；
- **容器 URL 的 404** 使用通用 404 页：提供站内搜索与五板块入口，**不针对部门段做部门化引导**（避免变相部门页观感；§3.2 的 404 语义不因 404 页文案改变）；通用 404 页同服务全部未知路径。

> 本节断言：IA-14，见附录 §13。
