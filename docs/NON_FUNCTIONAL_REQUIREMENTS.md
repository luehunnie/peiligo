## 1. 性能

> Human M7 增量 A：可重复测量标准覆盖首页/板块页/内容详情/搜索/归档五类；数据规模 200/1000/5000；指标含 p50/p95/基础并发。

### 1.1 测量环境

- **预发布同级配置**（02 S7.2 口径）：PRD §16 三环境中的测试/预发布环境（校园 PVE 主机，Ubuntu 虚拟机 + Docker）；正式生产服务器具体条件待确认（PRD §16；U5）→ 见 PP-08/PP-19。
- 网络口径＝学校正常网络；客户端＝常用桌面设备或同规格虚拟/实体机（记录 CPU/内存/浏览器版本）。
- **留痕要求**：每次测量记录环境规格、数据规模档、日期、脚本/数据集版本与原始结果并归档（Evidence），保证第三方可复现。

### 1.2 数据规模三档

- **200 / 1000 / 5000** 条内容三档（沿用 M6.1 数据集构造规则与语料配比，含种子，可重建）。
- **达标门档＝1000**（先验冻结，对齐 S6.1 口径与 PRD §14"接近正式环境的数据量"）；200/5000 档照测照记作观察项。
- 容量假设（§8：部门 ≤30、内容 ≤1 万条）经项目负责人确认（PP-16/PP-17）后，如需上调门档（如 5000/10000 档复测），同一指标继续适用。

### 1.5 资源预算（PRD §14"首页图片、附件预览和前端脚本必须受到约束"）

- **首页图片**：Wagtail rendition 响应式输出 + 原生懒加载（`loading="lazy"`）。
- **附件预览**：首页与列表页不内联展开附件内容；详情页附件以条目链接呈现，不做前台内嵌大文件预览。附件大小上限本身＝PP-01（SB 互见）。
- **前端脚本**：单页脚本预算默认 **≤ 200KB（未压缩）**〔02 S7.2 标记确认 → PP-09〕；服务端渲染、关键内容无阻塞脚本（ADR-0002）。预算核验＝构建产物体积统计，挂 B 阶段构建验收。

### 1.6 测量工具与可重复性要求

- **客户端**：Lighthouse（FCP），脚本化非交互运行。
- **服务端**：计时 instrumentation（中间件或等效手段）记录请求处理墙钟——不锁定具体实现，B 阶段落地。
- **并发**：负载生成工具候选 k6 / Locust / vegeta 任一，脚本入库可复跑（不锁定产品）。
- **可重复性**：固定数据集构造（M6.1 规则+种子）＋固定查询样本＋预热+20 次取样＋环境与结果留痕——第三方按本文可独立复现（对齐 POC SE-02 可复现精神）。

## 3. SEO 与 noindex（承接 IA，不重设计）

> Human M7 增量 D：sitemap、canonical、默认内容可收录、search/filter 状态 noindex、archive 规则、external confirmation page、content noindex、404——全部承接 IA §10 冻结位点，本文不新增语义。

### 3.1 位点表（承 IA §10，逐条挂 IA 断言）

| # | 页面/状态 | robots（meta） | sitemap.xml | 断言 |
| --- | --- | --- | --- | --- |
| 1 | 首页 `/` | 默认可收录 | 收录 | IA-10 |
| 2 | 板块页 ×5 | 默认可收录 | 收录 | IA-10 |
| 3 | 内容页（默认态） | 默认可收录 | 收录 | IA-10 |
| 4 | 内容页（**单篇 noindex** 态） | **noindex**（单篇字段置位） | **同步退出** | IA-09 |
| 5 | 部门容器 `/<板块>/<部门>/` | ——（**前台 404**，无可收录页面） | 排除 | IA-02/IA-03 |
| 6 | 板块筛选态（含 query 参数） | **noindex** | 排除 | IA-12 |
| 7 | 全站搜索页 `/search/`（含无参数态） | **noindex** | 排除 | IA-12 |
| 8 | 外链确认跳转页 | **noindex** | 排除 | IA-12 |

### 3.2 实现位点与机制口径（承 IA §10.1）

- **单篇 content noindex**：内容页模型布尔字段（编辑位＝后台 promote 侧），输出位＝全局模板 `<meta name="robots">`；置位时**同步退出 sitemap**（不发送矛盾信号）。
- **canonical**：query 态（筛选/搜索）一律输出 noindex 且 `<link rel="canonical">` 指向**去除全部 query 参数**的基础 URL（板块页/`/search/`）；内容详情 canonical＝自身绝对 URL。参数态不构成独立收录单元。
- **sitemap**：贡献位仅 #1–#3（未置 noindex 的 200 页面树节点）；生成机制＝MB13。sitemap 域名依赖 Site 记录与 `WAGTAILADMIN_BASE_URL`（现为占位值 `http://example.com`——production.py 现状）→ 部署阶段配置项，随 PP-19 确认。
- **redirects**：URL 变更经 `wagtail.contrib.redirects` 管理（INSTALLED_APPS 已装配——base.py 事实）。
- **robots.txt**：V1 不依赖、不新增 robots.txt 层面排除规则（容器 404 与 noindex 已覆盖 #4–#8——IA §10.1）。
- **archive 规则**：已过期内容不产生新收录面——到期内容仅经 #7 搜索态（HISTORICAL）可见并带「已过期」标注（M5.2），该态整体 noindex。
- **404**：容器与不存在路径返回 404 状态（IA-02）；404 模板属 §2.1 可访问性清单。

### 3.3 现状

## 4. 隐私与统计

> Human M7 增量 E：只用产品需求允许的最小数据；不做广告画像/跨站追踪/个人浏览画像；日志最小必要；搜索统计未来实现须匿名聚合优先；统计工具不选型。

### 4.1 允许收集的最小数据（PRD §12，四项，聚合口径）

页面访问（聚合计数）；搜索词；无结果搜索；筛选使用。**搜索统计未来实现时须匿名聚合优先**：搜索词/无结果/筛选使用统计以聚合计数存储，不与个人标识、会话或 IP 关联存储。

### 4.2 禁止项（PRD §12）

不建立学生画像；不记录个人浏览历史；不使用广告追踪；无跨站追踪；无 Cookie 画像。

### 4.3 日志最小必要（PRD §17；SB §6 同口径）

日志不记密码或敏感附件内容；应用日志仅记必要运维字段；访问日志默认含 IP——保留期默认建议 ≤ 90 天（PP-20），到期轮转/清理。

### 4.4 统计工具

**不选型**（Human 增量 E）——选型留 B 阶段决策；校内自托管分析为 PRD §12 候选方向。

### 4.5 现状

`PARTIAL`——约束已冻结；当前代码库无任何统计/追踪实现（"未做"即当前合规现状，随实现按 NF-12 核验）；日志框架与保留策略未配置（settings 无 LOGGING 配置——事实），`NOT_IMPLEMENTED` 部分。

## 5. 备份与恢复

> Human M7 增量 F：DB+Media；RPO、备份频率、恢复验证、数据一致性、media 完整性、发布前额外备份、恢复演练 Evidence 要求；已有正式数值则引用，未确认数值→§12。

### 5.1 范围、频率与 RPO

- **范围**：PostgreSQL 数据库 + 媒体文件**配套**备份（PRD §15），两者必须成套存储、成套恢复。
- **频率**：每日自动备份（PRD §15）。
- **RPO**：≤ **24** 小时（PRD §15"最多接受 24 小时数据损失"）。
- **发布前额外备份**：重要版本发布前额外备份（PRD §15）——触发点＝部署生产前，纳入发布流程清单。
- **审计日志**：保留 ≥ **1 年**（PRD §15）。

### 5.2 数据一致性

DB 备份须取一致快照（PG 逻辑备份或等效基础备份机制，工具 B 阶段定）；DB 与 media 备份在同一备份窗口内完成，并**互相登记对方备份集标识**（成套可核对）。

### 5.3 media 完整性

备份附产物清单（文件数 + 字节总量）；恢复时执行清单核对 + **抽样哈希比对**；文件名长度上限等存储口径见 PP-07（SB 互见）。

### 5.4 恢复演练

- **频次**：每季度全量演练（02 S7.2 默认建议 → PP-14）＋ PRD §15 强制的发布前备份。
- **RTO**：故障后 **24 小时内恢复服务**（PRD §16）；演练实测恢复耗时即 RTO 证据。
- **隔离红线**：演练在隔离环境进行，不得覆写测试/生产现有数据（PRD §16 测试与生产不共享）。

### 5.5 恢复演练步骤模板（冻结）

1. 以备份集在隔离环境起新容器（不触碰测试/生产数据）；
2. 恢复 DB 备份；
3. 恢复 media 并执行完整性校验（清单核对 + 抽样哈希）；
4. 应用启动（migrations 检查）+ 冒烟：首页 200、后台登录、执行一次搜索、读取发布排程字段；
5. 记录 Evidence 并判定 RTO。

**Evidence 要求（每次演练留档）**：日期、环境、备份集标识、DB/media 成套标识、完整性校验输出、实测恢复耗时（RTO）、异常与结论。载体由 B 阶段/部署阶段定（部署文档或工单）。

### 5.6 备份存放与保留

校方正式服务器条件待确认（PRD §16；U5 → PP-19）；飞牛系统仅评估为备份存储候选、不承载应用（PRD §16）；保留策略与副本数未定 → PP-15。备份结果监控见 §6 行 4。

### 5.7 现状

`NOT_IMPLEMENTED`——无生产环境、无备份脚本/任务；本节冻结口径、模板与 Evidence 要求。

## 10. 断言清单（NF 系列；每条含 Requirement / Measurement / Pass condition / Environment）

> NF-01–NF-06 为 02 S7.2 指定断言，纳入并扩展至 NF-17（可增不可减）。断言为**验收级可核对命题**，实测挂接 B 阶段/交付线（§13 Mapping），本文不执行、不写测试代码。

### NF-01 首页核心内容可见性
