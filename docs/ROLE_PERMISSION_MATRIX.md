## 0. 文档定位与读法

- 本矩阵是产品级权限语义的**单一事实源**：角色 × 对象 × 动作 × 允许/禁止，逐格附 PRD 条款号或"推导"标注（推导=由所引 PRD 条文直接推出，未新增能力，不构成 V1 扩围）。
- 它同时是 ADR-0004 决策 3 所留假设（"部门账号不持有任何 Snippet 权限，待 S4.1 正式确认"）的**正式确认文书**——见 §3.2。
- 单元格记法：**✅ = 允许**；**❌ = 禁止（负面权限）**；**➖ = 不适用**（该角色对此对象无此动作语义，或对象对该角色不成立）。"❌ 推导"同样是负面权限。
- 矩阵行编号 `M-A1`…`M-G5`，与 §6 测试 T01–T16 构成**双向索引**：每行有对应测试列，每条测试回引矩阵行与负面权限项编号（N01–N15）。
- 冻结原则（全文档有效，实现与测试均不得偏离）：
  1. **部门岗位账号只管自己部门的子树**：部门容器节点是其唯一授权锚点，出子树一律无权（PRD §4.3）。
  2. **部门岗位账号不能永久删除**：任何对象、任何路径（含自己创建的页面）均无永久删除权（PRD §8）。
  3. **部门岗位账号默认不管治理类**：Department、词表、受控标签、FeaturedItem、CarouselItem（首页轮播项，首页升级新增）、SiteSettings、用户与组、板块与容器结构，全部零权限（PRD §4.3；ADR-0004 决策 3）。
  4. **技术维护人员严格按矩阵行权，不凭常识扩权**：其职责在运维通道（依赖/备份/环境/恢复），不经 CMS 权限系统获得任何内容操作面（PRD §4.4"技术维护与日常内容管理是不同职责"）；§2.3 第 N11 条逐项列明其"无权"边界。

| 编号 | 角色 | 定义与数量 | 职责要点（PRD） | V1 承载形态 |
| --- | --- | --- | --- | --- |
| R1 | 总管理员 | V1 仅设置一名（PRD §4.2） | 网站基础配置、账号和板块管理；创建/停用/重置部门岗位账号；管理首页重要内容与置顶内容；处理跨部门纠错、内容下架和永久删除；维护无法由责任单位自行维护的校园固定信息；定期检查统一工作邮箱（PRD §4.2） | 专用 Django/Wagtail 组（全权限，见 §3.2），V1 恰一个账号 |
| R2 | 部门岗位账号 | 每个部门最多一个；账号属于岗位、不属于个人；同一时间只允许当前负责人使用；人员变更办理交接并立即重置凭据（PRD §4.3） | 只能创建、编辑、发布、下线和归档本部门内容（ADR-0004 引述口径："只能维护本部门内容"）；不得修改其他部门内容、网站配置、账号、板块或首页置顶状态（PRD §4.3） | 每部门一个 Django Group + 页面树权限（挂本部门容器节点，ADR-0004 决策 1） |
| R3 | 技术维护人员 | 项目负责人或其指定人员（PRD §4.4） | 依赖升级、安全修复和故障恢复；备份检查与恢复演练；测试、预发布和生产环境维护；运行监控与技术交接文档（PRD §4.4） | 无 CMS 内容权限；运维通道（OS/DB/部署）+ 唯一 superuser 账号（仅故障恢复，见 §3.2 边界说明） |
| R4 | 未登录访客（学生访客） | 无需登录（PRD §4.1） | 查看、搜索、筛选所有已公开发布的内容；不具备投稿、评论、报名或个人订阅能力；经统一工作邮箱报告错误（PRD §4.1） | 前台匿名访问，无任何后台账号（PRD §5 不开放公开注册） |

角色组合说明：同一自然人可以身兼多角色（例如项目负责人既是 R1 又是 R3），但**账号必须分离**——本矩阵约束的是账号，不是自然人；R1/R2/R3 权限不得合并进同一账号。

## 3. Wagtail 实现映射（§3）

### 3.1 实现方向锁定（冻结）

- **唯一方向**：Django Group + Wagtail 页面树权限（`GroupPagePermission`，挂部门容器节点向子树传播；权限类型 add/edit/publish/lock/unlock，上游审计 §3.2；GPP `permission_type` 实取 `add`/`change`/`publish`，见 §3.6）+ Wagtail/Django 自带认证（PRD §5 不自建独立用户中心；ADR-0004 决策 1"不自写权限逻辑"）。
- **禁止**（与 02 §0.2-2"不改核心"、PRD §5 一致）：自建 RBAC 表/体系、JWT 或任何自定义令牌、`admin_users` 之类的自定义账号表、Session 存部门 ID 判权、自写权限中间件或覆盖 Wagtail 权限类。部门归属判权只认树位置（容器绑定 Department，`departments/models.py` 已实现零漂移校验），**不存在"读 Session 里部门 ID 再比对"的代码路径**。
- 本矩阵不进入 M4.2（原型构建）与 M4.3（测试执行）；本文件仅定义配置与断言。

### 3.4 唯一已知张力与关闭措施（必测）

- **事实**（上游审计 §3.2＋A4.2 PoC 对 Wagtail 7.4.2 源码修正）：页面树权限类型为 add/edit/publish/lock/unlock，**没有独立 delete 类型**；且删除能力面比初版认知**更宽**——`change`@容器 ⇒ **可删子树内任意页**（不限归属、不限叶子：`PagePermissionTester.can_delete()` 在 `"change" in permissions` 时直接放行，`wagtail/models/pages.py:2246` 附近；仅"无 publish 且子树含 live 页"受附加限制，而部门组恰有 publish，不触发）；`add` 仅附带"删除自己拥有的页面"（ownership 窄面）。非叶节点删除另需 `bulk_delete_page` 模型权限——部门组不授 ⇒ 容器自身 can_delete=False，结构删除天然隔离（§3.2 部门组行）。
- **政策**（PRD §8）：永久删除仅由总管理员执行 → 矩阵 M-A8/N02 对 R2 全路径 ❌，包括删除自己创建的页面与上述 change 删除面的任何目标页。
- **关闭措施**（官方扩展点内，非自建 RBAC；A4.2 实测 61/61）：**双钩子**只拒绝守卫，缺一不可——① `before_delete_page`（单条删除视图 `POST /admin/pages/{id}/delete/`）；② `before_bulk_action`（批量删除 `POST /admin/bulk/wagtailcore/page/delete/`，`action_type=="delete"` 时拦）——批量动线 `DeleteBulkAction.execute_action` 直调 `page.delete(user=user)`，**绕过**单页钩子，故两钩都必须挂。两钩均在 `transaction.atomic()` 内、**返回带 status_code 的响应即短路返回并回滚**（"零库变更"语义成立）。M4.2 PoC 实测：无守卫时两条路径均可删（张力复现）；挂双钩后均拦截且快照 diff 为空（含修订与日志）；总管理员放行后仍须过默认 can_delete（其根级 change 满足），守卫从不新增授权、fail-closed。M4.3 以 T08 回归。
- **升级路径**：若存在官方扩展点无法覆盖的删除路径，按 ADR-0004 决策 4 升级 D5 决策门重议——**不得**改用自建权限体系兜底（§3.1 冻结）。A4.2 评审已扫描 Wagtail 7.4.2 admin 全部页面删除入口：仅上述单条视图与 `DeleteBulkAction` 两条，均被双钩子覆盖，无已知缺口。

### 3.6 实现注记（A4.2 PoC 实测事实，M4.3 编写测试的直接输入）

以下为 Wagtail 7.4.2 实测行为（M4.2 PoC 61/61 断言＋A4.2 独立评审对源码复核），实现与测试不得凭常识偏离：

- `GroupPagePermission.permission_type` 实取 `add`/`change`/`publish`——**不是 `edit`**（`change` 对应 codename `change_page`）；本矩阵行文沿用上游审计"edit"称谓处均指 GPP 的 `change`。
- 组配置实测形态：部门组＝GPP(add/change/publish)@本部门各容器＋Django 权限恰一枚 `wagtailadmin.access_admin`（进后台必要条件；PoC CHECK6 实证两组权限清单恰为 `[wagtailadmin.access_admin]`、`GroupCollectionPermission=0`）；总管理员组＝根级 GPP＋全量模型权限（含 `bulk_delete_page`）＋GCP@根集合（§3.2）。
- settings 编辑 URL 形态 `/admin/settings/{app}/{model}/{pk}/`，**pk 是 Site 的 pk**（视图 `get_object_or_404(Site, pk)` 再 `for_site`）；无 pk 形态只是 302 跳转——T11 构造 URL 时按 Site pk。
- StreamField 表单提交用 `body-count`/`body-0-type`/`body-0-value` 分片字段；RichText 值必须是 Draftail **ContentState JSON**（非 HTML 字符串）。
- 拒权 HTTP 表现是 **302 重定向**回后台首页并弹提示（已登录＋有 `access_admin` 时非 403），且 POST 成功同为 302——断言口径见 §6 通用拒绝断言。
