## 背景

1. **既有口径及其简化形态**：ADR-0002（C2）冻结的前端架构为 Wagtail 服务端模板、无 SPA；其决策节边界条件 2 原文已载明"静态资源（CSS/JS/图片）经 Django static 体系管理；**少量渐进增强脚本以独立静态文件加载，不构成 SPA**"。项目对外长期以简化的"SSR ＋ 零 JS"概括该口径（如 README 技术栈行、`templates/base.html` 内注释），该概括与 0002 原文之间存在解释空间。
2. **触发事件**：首页升级（2026-09-10 PRD）要求首页顶部新增可点击轮播（§4），含 2–5 项时自动播放、左右箭头、指示点、悬停暂停等交互（§10）——纯服务端模板无法承载自动轮播语义。PRD §16 明确要求"建议新增/更新 ADR，而不是默默违反旧 ADR"，并给出新口径与约束（不引入 npm／React/Vue／第三方轮播库；新增 `static/js/`；经 `base.html` 注入点加载；SSR 内容在 JS 失败时仍可访问）。
3. **数据基础已就绪**：轮播数据模型已实现并收口——`CarouselItem` Snippet 与五类内容页可选 `cover_image`（commit 21909e1，Phase 3.5 审查 PASS）；轮播**前台 SSR 模板与 JS 尚未实现**，属后续前端阶段。本 ADR 只冻结架构口径与边界，不描述、不预设任何未实现的前端细节。
4. **决策时机**：Phase 4（架构决策＋文档同步）按首页升级实施顺序在模型落地之后、前端实现之前落盘本 ADR，使后续前端阶段在明示口径内执行。

## 决策

逐字固化首页升级 Phase 2 冻结设计（与 PRD §16.1 一致，冻结不得重开）：

> **Peiligo 前台正式架构口径由简化的"SSR ＋ Zero JS"明确细化为：SSR-first ＋ Minimal Vanilla JS Progressive Enhancement（服务端渲染优先＋最小原生 JS 渐进增强）。**

边界条件：

1. **SSR HTML 仍是内容与链接的权威输出**：一切面向学生的内容、链接与页面结构均由服务端模板输出；任何信息不得只存在于 JS 侧。
2. **JS 只是渐进增强层**：原生 JavaScript（无框架、无转译）仅为已可用的 SSR 页面叠加交互增强；不存在"JS 渲染内容"路径。
3. **JS 失败降级**：JS 被禁用、加载失败或执行出错时，核心内容与链接必须仍可访问、可操作（轮播退化为可用的静态图文链接，而非内容不可达）。
4. **允许少量独立 static JS**：新增 JS 以独立静态文件置于 `static/js/`，经 `base.html` 既有/恢复的注入点（`extra_js`）按需加载；纳入现有 Django static／collectstatic 体系，不另起构建或服务链。
5. **首个正式场景＝首页轮播**：本口径的首个正式应用是首页 Carousel（数据模型已落地，前台实现归后续前端阶段）；在轮播前端落地前，本 ADR 不授权任何其他 JS 新增。
6. **禁止 npm／Node 构建链**：不引入 package.json、打包器、转译器或任何 Node 侧构建步骤；JS 以手写源码直接交付。
7. **禁止 React／Vue／SPA**：不引入任何前端框架，不建立 SPA 工程；ADR-0002 该边界原样有效。
8. **禁止第三方 Carousel library**：轮播交互以项目自有原生 JS 实现，不引入 Swiper 等第三方库。
9. **禁止扩大解释**：本 ADR 不得解释为"以后可以随意加 JS"——新增 JS 场景须逐案评估并以变更留痕（必要时新开 ADR）批准；"少量""渐进增强"是硬边界，不是默认通道。
10. **`prefers-reduced-motion` 必须被尊重**：全部 JS 驱动的动效须响应减弱动效偏好——减弱动效下取消或极大压缩过渡动画，并停止自动轮播，手动切换保持可用。
11. **与 ADR-0002 的关系**：本 ADR 是 0002 边界条件的细化与显式化，不推翻 0002；0002 的无 SPA、服务端模板、权限一致性等全部结论继续有效。

## 后果

**正面收益**：

1. 自动轮播等轻交互需求在不动摇 SSR 基座的前提下获得正当实现路径，消除"需求与旧口径冲突→默默违反"的风险（PRD §16 点名）。
2. ADR-0002 的六维优势（预览/SEO/部署/缓存/无障碍/权限一致性）全部保留——JS 不承载内容与链接，SEO 与降级可达性不回退。
3. 口径从简化口号回到精确表述："零客户端 JS **框架**"与"最小原生 JS 渐进增强"不再互相矛盾，文档与实现可互相对照验收。

**代价与权衡**：

1. 前台从此存在自有 JS 资产：须为其维护无障碍与 reduced-motion 行为，测试面新增 JS 行为断言（自动播放、切换、降级）。
2. "少量"为语义边界而非数值边界，新增场景的逐案评估依赖治理纪律（边界条件 9）；存在被渐进蚕食的长期风险，由复核时点对冲。

**受影响的后续步骤与产物**：首页升级后续前端阶段（Carousel SSR 模板＋`static/js/` 首个文件＋`base.html` 注入点恢复——该文件现有"全站无 JS"注释随实现阶段同批更新，不随本 ADR 提前改动）；文档措辞同步（CONTENT_MODEL 首页升级批次、发布指南、权限矩阵）已另行落盘。

**复核时点**：出现第二个 JS 应用场景提案时（逐案审批并检验是否仍属"少量"）；或轮播 JS 落地后验收发现降级/减弱动效语义无法满足时。触发任一信号即重估本边界，必要时新开 ADR。

## 替代方案

### 替代方案 1：维持严格零 JS（砍自动轮播或纯 CSS 方案）

- **方案描述**：维持"SSR ＋ Zero JS"简化口径字面执行，轮播降级为纯 CSS 切换或不做自动播放。
- **否决理由**：PRD §4/§10 明确要求 2–5 项时自动播放＋手动控制＋悬停暂停，纯 CSS 无法承载定时自动切换，也无法表达"减弱动效下停用自动播放"的完整语义；硬扛该方案等于砍已确认需求，或退回"默默违反 ADR-0002"的状态——两者均劣于明示口径（PRD §16 的设置本意）。
- **遗留风险**：无（被否决方向不产生遗留）。

### 替代方案 2：引入前端框架或第三方轮播库（React/Vue/Swiper 等）

- **方案描述**：以框架组件或成熟轮播库实现 Carousel，获得现成的自动播放／无障碍能力。
- **否决理由**：PRD §5 非目标与 §16.2 约束明令禁止 npm/React/Vue/第三方轮播库；违反 ADR-0002 无 SPA、无前端构建链的冻结边界；为单一低交互组件引入框架与构建链，体积、维护面与部署链成本显著不成比例（违背最简实现原则）。
- **遗留风险**：轮播无障碍细节（焦点管理、按钮语义）须自研并测试——已列入前端阶段验收与边界条件 10。
