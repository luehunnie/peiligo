## 背景

- **决策触发与权限**：载体分配（原决策门 D6）已由项目负责人确认即 **C4**，属 OR-4"已确认决策即基线"；本 ADR 只做固化与论证记录，不重开选型、不重开讨论。
- **要解决的问题**：V1 内容模型设计（M3.1，引源 02 §4 S3.1）需要一张**逐类内容的载体分配原则表**作为直接输入；载体选择直接决定 URL 结构、权限模型面（S4.1 Snippet 权限简化依据）、前台模板与搜索接入面。
- **上游证据**（`docs/audit-report-wagtail-upstream.md`）：
  - **§3.1（内容模型，PRD §7）**：六类内容形态存在两种官方一等载体——**Page**（独立 URL、独立模板、加入树形导航）与 **Snippet + SnippetViewSet**（结构化记录 + 聚合列表；可按需混入 `DraftStateMixin`/`RevisionMixin`/`PreviewableMixin` 等获得草稿、预览与发布排程）；审计明确"具体每类选 Page 还是 Snippet 属技术设计决策"，两者皆官方扩展点、无需修改 Wagtail 核心。
  - **§4（官方推荐项目结构与落地建议）**：`wagtail start` 骨架按域拆 app 的建议中，曾把 guides 列为 Snippet、resources 标注"Snippet 或 Page"——该建议提出于 C4 确认之前，本 ADR 按 C4 修正其载体归属（见"替代方案"第 1 项）。
- **PRD §7 约束**：六类面向学生内容（通知 PRD §7.1 / 文章 PRD §7.2 / 活动结构化字段 PRD §7.3 / 学习资料 PRD §7.4 / 软件与工具 PRD §7.5 / 校园指南 PRD §7.6）均面向公开访问，带独立 URL、预览、SEO、发布排程与搜索需求；PRD §7.2 要求**"不为减少模型数量强行混用"**不同内容形态。
- **本 ADR 边界**：只定**载体级**分配总则；字段级设计留给 M3.1（02 §3 S1.6），**活动类的结构化字段挂载方式（EventFieldsMixin）终判显式留给 M3.1**。

## 决策

**C4 逐字引用固化**（00_MASTER_PLAN §2.1，不得改写语义）：

> 内容载体：所有面向学生且需独立 URL/预览/SEO/发布/搜索的通知、文章、活动、学习资料、软件工具、校园指南均为 **Page**；部门/受控类别/标签/站点配置用 **Snippet/设置**。活动类通过 Notice/Article Page 上的 EventFieldsMixin 结构化字段承载（M3.1 终判），载体仍为 Page，不违反本条

### 硬规则

任何后续设计**不得**把上表 Snippet/设置项改为公开 URL 内容，**反之亦然**——载体归属一旦需要变更，必须新开 ADR（原 ADR 转 Superseded），不得在实现步骤内静默改判。

**一句话可检验**：六类面向学生内容（通知/文章/活动/学习资料/软件与工具/校园指南）载体均为 Page；部门、受控类别、标签、首页推荐位为 Snippet；站点级配置为 settings；活动类的结构化字段挂载方案不在本 ADR 终判、显式留待 M3.1。

## 后果

**正面收益**：

- M3.1 内容模型细化获得直接输入；其分级 A 测试要求即"载体表与 C4/ADR-0005 零冲突"。
- 权限设计面收窄：V1 默认部门岗位账号不持有 Snippet 管理权限，当前无需实现 Snippet per-instance 隔离（S4.1 简化依据；与 ADR-0004 决策 3 一致）；页面树只承载公开内容，与 ADR-0004 部门容器树分工清晰。
- 前台、SEO、站点地图与搜索（M4/M5）只需面向 Page 接入；Snippet/设置不进入公开路由。

**代价与权衡**：

- 校园指南目录、软件列表等聚合页须基于 Page 查询/索引实现（放弃 SnippetViewSet 聚合列表的现成形态），模板与视图工作量小幅增加。
- V1 默认部门岗位账号不持有 Snippet 管理权限，因此当前不需要为部门账号实现 Snippet per-instance 隔离。若 M4.1 角色权限矩阵后续明确授予某类 Snippet 给部门岗位账号，则必须通过 Wagtail 官方扩展点设计对应 permission_policy，并加入越权测试；不得提前实现。
- Page 类型数量较多——这是 PRD §7.2"不为减少模型数量强行混用"的直接要求，接受。

**受影响的后续步骤与产物**：M3.1（载体表零冲突核对）、M3.2（字段级设计）、S4.1/M3.x 权限步骤、M2.x 信息架构（URL 结构）；本文件即 `docs/adr/0005-page-vs-snippet-allocation.md`。

**复核时点**：G1 架构冻结门（项目负责人复核并设 Accepted）；M3.1 完成时核对 EventFieldsMixin 终判与本 ADR 零冲突；此后按 00 §6 门节奏，任何载体变更须新 ADR。

## 替代方案

1. **校园指南 / 软件与工具改用 Snippet + SnippetViewSet 聚合列表**（上游审计 §3.1 曾列为适合"结构化记录 + 聚合列表"的形态、§4 早期建议曾把 guides 列为 Snippet）→ 否决：C4 已确认六类面向学生内容均需独立 URL/预览/SEO/发布/搜索=Page（OR-4 不得重开）；Snippet 无公开独立 URL。遗留风险：聚合列表页工作量转移至 Page 查询实现（见后果）。
2. **本 ADR 提前终判活动类字段级挂载**（直接锁定 EventFieldsMixin 挂 Notice/Article、不建独立类型）→ 否决：越权——活动载体已冻结为 Page；M3.1 仅终判 EventFieldsMixin 的具体挂载方式 / NoticePage、ArticlePage 的类型组织方式（00 §8 M1.6 阶段目标；SE-A06 表述按 G1 前定向修复校正）；本 ADR 只固化"载体=Page"与预期挂载方式。遗留风险：M3.1 若否决预期挂载方式，须核对与 C4"载体仍为 Page"表述的相容性并在 M3.1 产物中留痕。
3. **站点级配置（紧急提示、统一反馈邮箱、跳转页文案）用 Snippet 承载** → 否决：站点级单例配置适用 Wagtail settings（BaseSetting）；为单例建可多实例的 Snippet 会引入误配多实例风险。遗留风险：无实质风险，仅需将 settings 编辑权限收归管理员侧。
4. **全部内容用 Snippet + 自建前台路由（不建页面树）** → 否决：放弃 Wagtail 页面树、预览、发布排程、树形权限的内建能力，与 C4 相悖且与 C2（服务端模板，ADR-0002）基座冲突；自建路由属扩围（OR-5）。遗留风险：无。
