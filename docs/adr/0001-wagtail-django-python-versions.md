## 背景

后续所有实现步骤（M1.3–M1.6 各 ADR、M6.1/M6.2 搜索 PoC 环境、B1 项目骨架与依赖清单）都需要唯一的版本依据；版本组合属技术架构决策，必须在骨架建立（B1）与依赖首次锁定前冻结，避免"边写边选版本"造成返工。该组合已由项目负责人在基线确认中拍板（C1，冻结不得重开，OR-4）；本 ADR 仅做固化、论证与当日复核留档，不重新选型。

依据与证据（逐条可独立追溯）：

- **上游审计 §2.1**：截至 2026-08-15，PyPI 最新稳定版 Wagtail **7.4.2**（2026-06-15）；`8.0rc1`（2026-08-13）为 pre-release；官方日程 8.0 计划 2026-08-25 发布。
- **上游审计 §2.2**：7.4 为 LTS（上游 `docs/releases/7.4.md`："Wagtail 7.4 is designated a Long Term Support (LTS) release"，维护更新持续至下一 LTS）；**7.4 LTS 安全/数据修复支持至 2027-11-02**；8.0（特性版本）安全支持仅至 2027-02-02、活跃支持至 2026-11-03；7.0 LTS 支持止于 2026-11-02（即将到期，不可选）。
- **上游审计 §2.3**：官方兼容矩阵（上游 `docs/releases/upgrading.md:88-91`）——Wagtail 7.4 LTS ↔ Django 5.2/6.0 ↔ Python 3.10–3.14；Django 6.1 已被 Wagtail 上游撤回正式支持（main 提交 `024a2f07f5`，2026-08-13）；Django 官方支持表：5.2 LTS 扩展（安全）支持至 2028-04；Python 3.13 EOL 2029-10（3.10 → 2026-10 即将到期，不选）。
- **上游审计 §2.4**：候选 A（Wagtail 7.4.2 LTS + Django 5.2 LTS + Python 3.13，三层支持窗口重叠最长）为审计推荐项，经项目负责人确认为 C1。
- **02_ARCHITECTURE_DOMAIN_PLAN §3 S1.2**：本 ADR 必含六要素——冻结组合、支持窗口、8.0 取舍、modelsearch 联动说明、复核时点、复核命令。
- **PRD §17 升级节奏、§19 决策门 2**：季度升级/月度安全检查的低维护节奏约束与版本决策门出处（经 02 S1.2 测试要求回溯引用）。

## 决策

冻结如下版本组合（C1 逐字引用固化，不得改写语义）：

> 版本组合：Wagtail 7.4.x LTS + Django 5.2 LTS + Python 3.13。首次锁依赖时（M1.2 / MB1）复核最新安全补丁后冻结具体补丁号；约束 `wagtail>=7.4.2,<7.5`、`django>=5.2,<5.3`、`modelsearch>=1.3.2,<1.4`；不采用 8.0 线（含 RC）与 `main`

展开为四项可检验约束（SE-A02）：

1. `wagtail>=7.4.2,<7.5`（7.4 LTS 线内取补丁）
2. `django>=5.2,<5.3`（5.2 LTS 线内取补丁）
3. Python `3.13`（运行时 3.13.x）
4. `modelsearch>=1.3.2,<1.4`（Wagtail 官方搜索栈拆分包，1.3 线内取补丁）

**当日版本复核（复核日期：2026-08-18；下列 URL 当日全部访问核验）**

| 复核项 | 当日事实 | 官方来源 URL |

**复核结论**：7.4.x 线无晚于 7.4.2 的补丁 → **实际锁定 `wagtail==7.4.2`**（约束区间 `>=7.4.2,<7.5` 满足且不变）；Django 5.2 线最新安全补丁为 5.2.17（2026-08-04）→ B1 首次锁依赖时应落在 `>=5.2.17` 的 5.2.x（策略区间仍为 `>=5.2,<5.3`）；modelsearch 1.3 线最新为 1.3.2 → **实际锁定 `modelsearch==1.3.2`**（区间 `>=1.3.2,<1.4` 满足）。

## 后果

- **正面收益**：三层支持窗口（Wagtail→2027-11-02、Django→2028-04、Python→2029-10）为可行组合中重叠最长；"双 LTS"与 PRD §17 季度升级、月度安全检查的低维护节奏匹配，V1 生命周期内无强制大版本升级压力。
- **代价与权衡**：放弃 8.0 线的新特性（API v3 / Django Ninja、自定义基类 Page 模型、全局权限策略注册表——审计 §2.4 候选 B 所列收益，留作 V2 演进点）；须持续跟进 5.2.x 安全补丁（5.2.17 已含 4 项 CVE 修复，B1 锁定时必须纳入）。
- **受影响的后续步骤与产物文件**：M6.1/M6.2（搜索 PoC 环境按本版本）；B1（后续计划，首次锁依赖——**B1 时依赖清单必须与本 ADR 约束一致**，若发现区间内无可满足组合，停下上报，不得代决）；`requirements*.txt` / `pyproject.toml`（根依赖清单，共享文件，00 §4.4）。
- **复核时点**：G1 冻结时复核一次；B1 骨架建立（首次锁依赖）时复核并冻结具体补丁号；此后每季度评估；上线前复核（PRD §17）。
- **复核命令**（当日事实核验，输出与本 ADR"当日版本复核"表比对）：

  ```bash
  curl -s https://pypi.org/pypi/wagtail/json | python3 -c "import sys,json;print(json.load(sys.stdin)['info']['version'])"
  curl -s https://pypi.org/pypi/django/json | python3 -c "import sys,json;print(json.load(sys.stdin)['info']['version'])"
  curl -s https://pypi.org/pypi/modelsearch/json | python3 -c "import sys,json;print(json.load(sys.stdin)['info']['version'])"
  ```

  说明：若复核发现 7.4.x 线出现晚于 7.4.2 的补丁，锁最新安全补丁并回写本 ADR 复核记录（约束区间仍满足 `>=7.4.2,<7.5`）；若发现 7.4 线意外终止支持（低概率），停下升级，不得代决。

## 替代方案

- **方案 B：Wagtail 8.0 线（含 RC）+ Django 6.0 + Python 3.13/3.14** → 否决理由：① 截至复核日 8.0 尚未正式发布（仅 `8.0rc1`；正式计划 2026-08-25），RC/首发无补丁沉淀（审计 §2.1）；② 支持窗口短——8.0 安全支持止 2027-02-02、活跃支持止 2026-11-03，2026-11 即需升 8.1（审计 §2.2）；③ 其收益服务于前后端分离等 V1 无此诉求的场景（审计 §2.4 候选 B；PRD §20 不扩围）→ 遗留风险：V2 若需 8.0 特性，届时需一次跨版本升级，由"复核时点"的季度评估吸收。
- **方案 C：Wagtail 7.4.2 LTS + Django 6.0** → 否决理由：Django 6.0 扩展支持 2027-04 止，短于 5.2 LTS（2028-04），且 V1 不需要 6.0 特性——无收益、纯增风险（审计 §2.3、§2.4 候选 C）→ 遗留风险：无。
- **方案 D：Django 6.1（当日最新稳定版）** → 否决理由：已被 Wagtail 上游撤回正式支持（main 提交 `024a2f07f5`，2026-08-13，django-ninja 上界所致），选 6.1 即失去 Wagtail 官方支持（审计 §2.3）→ 遗留风险：无。
- **方案 E：Python 3.10 或 3.14** → 否决理由：3.10 EOL 2026-10 即将到期；3.14 虽在官方兼容矩阵（3.10–3.14）内，但生态包兼容面略保守，3.13 为当前稳定版且距 EOL（2029-10）足够远（审计 §2.3、§2.4）→ 遗留风险：3.14 的性能改进暂不可用，V2 复核时点再评估。
- **方案 F：跟踪上游 `main` 分支** → 否决理由：`main` 为移动目标，无发布承诺、无支持窗口、无补丁纪律，与"跟随官方稳定发布"的项目约束冲突（02 §0.2-2 不修改 Wagtail 核心的同一精神）→ 遗留风险：无。
- **方案 G：modelsearch 不设 `>=1.3.2,<1.4` 区间、独立演进** → 否决理由：modelsearch 为 Wagtail 官方（wagtail org）搜索栈拆分包，须与所选 Wagtail 7.4 线保持 1.3 线联动；放开区间会引入未经官方组合验证的漂移（当日复核其 1.3 线最新 1.3.2 依赖 `Django>=4.2`，与 Django 5.2 兼容）→ 遗留风险：1.4+ 的改进须待本 ADR 复核时点统一评估后解锁。
