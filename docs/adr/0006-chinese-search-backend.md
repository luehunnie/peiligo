## 背景

- **要解决的问题**：PRD §10 站内搜索的后端选型（D7，ADR 索引中唯一真正待裁决项）。PRD §10 简单优先："首版优先评估 PostgreSQL 与 Wagtail 自带搜索能力；只有验证不达标时才评估独立搜索服务"。三候选零胜者预设（CONTENT_MODEL §22；报告 §1）：E1＝Wagtail DB 后端 icontains fallback、E2＝同后端 PG FTS＋`SEARCH_CONFIG='simple'`、E3＝PG FTS＋zhparser。
- **决策门与规则先验冻结**：D7 为保留决策门（00 §2.2）；达标判据（hit@10≥90%，200/1000 两门档；1000 档逐条 p50<1s）与决策规则（E1 达标→E1；E1 不达标、E2 达标→E2；E1/E2 不达标、E3 达标→E3；均不达标才评估独立搜索服务且须项目负责人批准）在实验前冻结（报告 §4.1/§4.2/§4.4；PRD §14"普通搜索请求约 1 秒内返回"）。裁决＝规则机械映射，不引入实验外判断。
- **M6 实验概述**（`docs/POC_SEARCH_REPORT.md`）：M6.1 方案章（§1–§4——三候选消费同一字段契约〔CM §20.1〕、真实中文语料三档 200/1000/5000、30 条金标查询、9 组合执行矩阵）；M6.2 执行（§5——9/9 组合完成：hit@10 全部 30/30=100%，1000 档逐条 p50 最大 E1=9.12ms／E2=14.53ms／E3=14.61ms，全部 <1s；执行评审 FAIL→勘误 bc4c79c→复评 PASS）；M6.3 证据压缩与 D7 裁决（§6–§7）。
- **生产落地前提的机制来源**：生产库为 PostgreSQL；`wagtail.search.backends.database` 按连接 vendor 分派（CM §20.0 事实 10）——PG 连接走 FTS 路径（＝E2 语义），icontains fallback 不可达；E1 PoC 以 SQLite vendor 触发（报告 §1.1、§8 D-5）。故 E1 若中选，其语义在生产成立须显式后端选择——本前提属事实登记，非新开设计。

## 决策

按报告 §4.4 冻结规则对 M6 实测做机械映射：**E1 双门达标（hit@10 三档均 30/30；1000 档逐条 p50 最大 9.12ms < 1s）→ 选定 E1＝Wagtail DB 后端 icontains（最简单优先）**。

D7 裁决（GPT 会话 M6.3-D7-search-decision，2026-08-31）逐字段引用固化：VERDICT=CLEAR_WINNER；SELECTED=E1；RATIONALE 逐字引用：

> 证据包§2、§3显示E1在质量门两档均30/30（100%），1000档逐条p50最大9.12ms，分别满足报告§4.1的hit@10≥90%及§4.2的逐条p50<1s。依证据包§7/报告§4.4首条"E1达标→E1"机械裁决；报告§5.2–§5.3数据完整支持门判定，未见内部矛盾。

**生产语义落地前提（PRODUCTION_IMPLEMENTATION_REQUIRED=YES）**：生产库为 PostgreSQL，`wagtail.search.backends.database` 在 PG vendor 下走 FTS 路径＝E2 语义（CM §20.0 事实 10）；E1 的 icontains 语义须在**显式选择 fallback/DatabaseSearchBackend** 才成立。落地方案属后续实现阶段——本 ADR 仅记录前提与验证义务，M6 不改任何生产代码/搜索配置/依赖；生产接线前须按报告 §7 限制补规模/并发验证与排序体验监测。

**状态边界**：本 ADR 2026-08-31 以 Proposed 落盘（README §4：代理不得代决）；同日经 G2 门项目负责人签收由 Proposed 转 Accepted（变更注记见状态字段头）。裁决书 ADR_STATUS=ACCEPTED_READY 释义＝"具备受理条件、待受理"（裁决时点口径）——该受理已由 2026-08-31 G2 门签收完成。

**一句话可检验**：按 §4.4 冻结规则机械选定 E1（Wagtail DB 后端 icontains）；其在生产 PostgreSQL 下成立的前提＝显式后端选择，生产接线属后续实现阶段并须验证（PRODUCTION_IMPLEMENTATION_REQUIRED=YES）。

## 后果

**正面收益**：

- 零新增基础设施：不加扩展、不加服务、不换后端类——沿用现状默认 `wagtail.search.backends.database`（CM §20 现状衔接）；实现最简（icontains 语义，无 FTS 配置面）。
- 两门均以 ≥1 个数量级余量通过（报告 §5.2/§5.3）；200/5000 档观察数据同步在档。

**代价与权衡**：

- 子串匹配无相关度排序（CM §20.2）：结果按 `-first_published_at` 排序（报告/CM §21.6 保序旋钮）；hit@10 为集合命中口径，排序质量未评。
- 生产实现需显式后端选择与验证（PRODUCTION_IMPLEMENTATION_REQUIRED=YES）：PG 下默认后端类走 FTS 路径，icontains 语义非默认可达；接线方案、验证与监测归后续实现阶段。
- E1 结构性差异随选型带入（CM §20.2）：RelatedFields 文本缺席（部门名/标签名/词表名不经 RelatedFields 命中）、boost 被忽略、StreamField body 为 JSON 存储原文子串匹配（含块类型键名误命中面）——M6 实测 30/30 金标下未构成失分，长期体验靠监测信号兜底。

**受影响的后续步骤与产物**：后续实现阶段的生产接线与验证（M7.2 端到端性能口径输入＝报告 §4.2/§5/§7）；字段契约与筛选维度不受选型影响（CM §22 对接点①——方案无关层）；本文件即 `docs/adr/0006-chinese-search-backend.md`。

**复核时点**：生产接线后按报告 §7 限制做规模/并发复测；排序体验监测信号（误命中、排序体验类反馈）出现时重评；如需更换后端，新开 ADR 并将本件转 Superseded（README §4）。

## 替代方案

1. **E2＝PostgreSQL SearchBackend＋`SEARCH_CONFIG='simple'`** → 未选：实测达标（hit@10 30/30、1000 档逐条 p50 最大 14.53ms）但按 §4.4 冻结规则劣后——规则首条"E1 达标→E1"，不引入规则外标准；`simple` 不分词，中文整串成单 token（报告 §5.4）。遗留风险：无（数据留档报告 §5.3，若 E1 生产验证失败可据既有数据复评）。
2. **E3＝PostgreSQL＋zhparser 扩展** → 未选：实测达标（hit@10 30/30、1000 档逐条 p50 最大 14.61ms、E3×5000 逐条 p50 最大 69.47ms）但按规则劣后于 E1，且运维负担更重——需镜像内编译 SCWS+zhparser、每库建 zhcfg（报告 §5.6），扩展维护风险随 PG 版本升级累积。遗留风险：无。
3. **独立搜索服务（Elasticsearch/OpenSearch 类）** → 未选：按 §4.4 第 4 分支不触发——E1 已达标，且 PRD §10 简单优先明确"只有验证不达标时才评估独立搜索服务"；M6 全程零独立搜索服务候选（报告红线）。遗留风险：无。
