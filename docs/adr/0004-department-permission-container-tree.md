## 背景

本项目需要为"各部门只能维护本部门内容"（PRD §4.3）选择 Wagtail 权限结构，同时满足"不建部门主页"的产品约束（PRD §6、§20——"部门独立主页"属 V1 不做清单，02 §0.2-3/§0.2-5）。项目负责人已确认决策 C3（D5，00 §2.2）：

> 权限结构：部门权限容器树——各部门容器节点承载权限；**无前台部门主页**：容器节点前台返回 404（或等效不可达），不得进入导航、站点地图、默认列表与默认搜索结果

（逐字引自 00_MASTER_PLAN §2.1 C3 行；02 §0.1 C3 行同义："部门权限采用容器树（各部门容器节点承载权限），且容器节点不得形成前台部门主页"。）

技术依据（上游审计 `docs/audit-report-wagtail-upstream.md` §3.2，全部为官方扩展点、无需改核心）：

- **页面树权限机制**：Add/Edit/Publish/Lock/Unlock 挂在树节点上并向子树传播（上游审计引用 `docs/topics/permissions.md:13-40`）；**Add 权限 = 只能编辑/删除自己拥有的页面**——"部门只能维护本部门内容"天然成立。
- **结构选项必须二选一**（内容模型冻结前）：(a) 板块下按部门建隐藏容器节点（权限挂在各部门节点上，树形传播自动隔离）；(b) 扁平结构 + ownership（详见"替代方案"节）。
- **D5 边界**（00 §2.2）：C3 已确认；M4.2/M4.3 仅为实现验证，若发现不可修复缺陷升级为决策门重议。

触发事件：M1.5 步骤（00 §8 M1.5；02 §3 S1.5）要求将 C3 固化为本 ADR；本 ADR 为 G1 架构冻结门检查表第 4 项。

## 决策

1. **容器树结构（上游审计 §3.2 方案 a）**：每个板块节点下按部门建立容器节点（部门权限容器），页面树权限（Add/Edit/Publish/Lock/Unlock）挂在各部门容器节点上并向子树传播；部门内容页以本部门容器节点为**唯一父级**。部门账号 = Django Group + Wagtail 组权限（绑定到容器节点）；部门隔离由树形权限传播天然成立，不自写权限逻辑。
2. **硬约束：容器节点不构成前台部门主页**。容器节点是权限容器/路由分组，不是内容页：
   - 前台访问容器节点 URL 返回 **404（或等效不可达）**；
   - **不进入导航、站点地图（sitemap）、默认列表与默认搜索结果**；
   - URL 方案可含部门段，但该 URL **不渲染任何部门聚合页**（URL 与路由细则留给 S2.1/M2.1）；
   - "部门筛选结果页"不是部门主页（02 §0.2-3；PRD §6、§20）。
3. **Snippet 侧简化假设（V1）**：部门账号不持有任何 Snippet 权限——词表（受控类别/标签）、部门数据、推荐位均由总管理员管理（待 S4.1 角色权限矩阵正式确认）。上游审计 §3.2 记录了 Snippet 自定义 `permission_policy` 官方扩展点，V1 不启用。
4. **验证生效条件**：本决策须经 S4.2 原型构建（丢弃式）与 S4.3 越权测试矩阵验证，**生效条件 = S4.3 越权矩阵全绿**（结论由 M4.3 回写本文"验证证据"节）；若 S4.3 发现不可修复缺陷，本 ADR 回 Proposed 并触发 D5 决策门重议（02 §3 S1.5 失败回滚条款）。

## 后果

**正面收益**

- 部门隔离复用 Wagtail 原生树形权限传播，零自写权限代码（上游审计 §3.2："树形传播自动隔离"），不修改 Wagtail 核心（02 §0.2-2）。
- 从结构上规避方案 b 的 Publish 横向越权面（见"替代方案"节）。
- 后台页面树浏览结构与权限边界一致，部门编辑的心智模型简单。

**代价与权衡**

- 树深度增加一层（板块 → 部门容器 → 内容页）；容器节点数量 = 板块 × 有内容的部门，建容器规则（如仅为确有内容的部门建容器）留给 S2.1/M2.1。
- "404/等效不可达、不入导航/sitemap/默认列表/默认搜索"需在 S2.1（树结构与 URL）、S2.2（导航/搜索/noindex 位点）与 S4.2/S4.3（原型与越权矩阵）逐项落实并实测，是 S4.3 测试矩阵的必测项。
- 部门维度的前台可见性只能由"筛选结果页"承载（≠部门主页），筛选语义细则留给 S2.1/S2.2。

**受影响的后续步骤与产物**

- M2.1/S2.1：站点树、部门容器树结构与 404 语义、URL 方案（`docs/INFORMATION_ARCHITECTURE.md`）。
- M2.2/S2.2：导航、默认列表/默认搜索对容器节点的排除、SEO/noindex 位点。
- M4.1/S4.1：角色权限矩阵中容器节点授权行（含本 ADR 第 3 条 Snippet 假设的正式确认）。
- M4.2/S4.2、M4.3/S4.3：丢弃式权限树原型与越权测试矩阵执行（`docs/POC_PERMISSION_REPORT.md`，结论回写本文）。

**复核时点**：G1 架构冻结门（项目负责人将本 ADR 设为 Accepted）；M4.3 PoC 结论回写时（全绿→维持；不可修复缺陷→回 Proposed 并升级 D5 重议）；其后随 S7.1 安全基线与上线前复核抽查。

## 替代方案

**方案 b：扁平结构 + ownership + 后台可见性过滤（否决）**

- 描述：全部内容直接挂板块节点，不建部门容器；部门账号仅靠 ownership（Add 权限 = 只能编辑/删除自己拥有的页面）维护本部门内容；后台用 `construct_explorer_page_queryset` hook（上游审计引用 `docs/reference/hooks.md:1087`）过滤各部门可见页面。
- 否决理由（上游审计 §3.2 原文）：板块节点上的 **Publish 权限允许部门发布/下线该节点下任何部门的页面（Publish 与 Edit 独立），存在横向越权面**，需 `construct_explorer_page_queryset` 过滤可见性并**接受残余风险**——"(a) 更干净"。即：该过滤只改变后台列表可见性，不消除权限面本身——持有板块级 Publish 权限的部门账号仍可发布/下线其他部门的页面，属必须长期接受的横向越权残余风险。
- 遗留风险：未采用，无遗留。若 S4.3 证伪方案 a 并按 D5 重议，方案 b 连同其残余风险一并重新评估（预期仍不采用，除非项目负责人裁决）。
