# Peiligo 内容发布指南

写给:**网站运营人员、各部门负责发布内容的同事**。这篇讲「业务」——什么内容适合发、发到哪个板块、选哪种类型、发布前后要做什么;后台每一步怎么点,见姊妹篇 [DEPARTMENT_EDITOR_GUIDE.md](DEPARTMENT_EDITOR_GUIDE.md)。**不需要任何编程知识。**

---

## 1. 总流程

一条内容从手头到学生看见,完整走这条路:

```
收到内容 → 确认适合公开 → 选板块 → 确认发布部门 → 选内容类型
        → 整理资料 → 后台建草稿 → 预览 → 发布前检查
        → 立即发布(或定时发布) → 前台复核
        → 后续:修改 / 下线 / 到期 / 归档
```

逐段说明:

1. **收到内容**:部门交给你的通知、活动、资料、文件等;
2. **确认适合公开**:面向全校学生公开的内容才发(涉密、内部讨论、未定稿、个人信息一律不发,拿不准就问部门负责人与网站管理员);
3. **选板块**:内容属于五大板块中的哪一个(见 §2、§3);
4. **确认发布部门**:内容以哪个部门名义发布——网站要求「内容归属的部门」与「存放位置」一致;
5. **选内容类型**:五类之一(见 §4);
6. **整理资料**:文字定稿、图片备好、链接确认可访问(见 §5);
7. **后台建草稿**:登录网站后台,在自己部门的目录下新建内容页,逐项填写;
8. **预览**:发布前先看实际展示效果;
9. **发布前检查**:对照 §7 的检查表过一遍;
10. **发布**:立即发布,或定时发布(设定将来的上线时间);
11. **前台复核**:发布后回到前台把页面当一名普通学生再读一遍(链接、图片、错别字);
12. **后续**:内容有变化就修改;需要撤下就下线;过有效期的内容自动进入「历史归档」,不会被删除。

## 2. 五大板块说明

全站固定五个板块,名称与定位冻结,不随运营临时增减:

### 校园纪事(`/chronicle/`)

- **适合**:校内新闻、通知公告、部门动态、成果报道等图文内容;
- **不适合**:带具体开始/结束时间的活动预告(发「校园活动」)、可下载的资料文件(发「学习资料」);
- **典型例子**:「我校举办秋季运动会开幕式」「关于图书馆调整开放时间的通知」。

### 校园活动(`/events/`)

- **适合**:有明确开始/结束时间的活动——讲座、比赛、社团活动、报名通知;发布时需填写活动开始/结束时间,线下活动还须填活动地点(线上活动勾选「线上活动」即可);
- **不适合**:泛泛的活动回顾(没有时间要素的回顾性报道发「校园纪事」更合适);
- **典型例子**:「12 月 9 日程序设计竞赛报名」「周五下午就业讲座」。

### 学习资料(`/materials/`)

- **适合**:课件、讲义、题库、模板等学习资料,以**文件附件**(由总管理员协助上传)或**外部链接**形式提供,并按学科·专业方向、资料类型分类;
- **不适合**:纯资讯类文章(发「校园纪事」)、软件本体(发「软件与工具」);
- **典型例子**:「高等数学期末复习提纲(PDF)」「毕业论文模板下载」。

### 软件与工具(`/software/`)

- **适合**:推荐给学生的软件与在线工具——介绍用途、适用平台(如 Windows / macOS / 手机),给出**官方下载或第三方网盘链接**与授权/费用说明;网站**不直接托管安装包**;
- **不适合**:文档资料(发「学习资料」)、校内新闻(发「校园纪事」);
- **典型例子**:「免费的 PDF 阅读器推荐」「校园网盘使用指南与客户端下载地址」。

### 校园指南(`/guide/`)

- **适合**:长期有效的说明性内容——办事流程、规章制度解读、设施使用说明、新生指南;它不是一篇「文章」,而是一张结构化的「服务卡片」:服务名称、地点、开放时间、联系方式、责任单位、维护方式、最后确认日期;
- **不适合**:有时效性的通知(发「校园纪事」);
- **典型例子**:「图书馆借书流程」「校医院就诊指南」。

## 3. 「我应该发到哪里?」速查表

| 我要发的东西… | 板块 | 内容类型 |
|---|---|---|
| 一条正式通知(有截止/有效期) | 校园纪事 | 通知页 |
| 一篇新闻或报道 | 校园纪事 | 文章页 |
| 一个带时间的活动预告 | 校园活动 | 通知页(填活动信息) |
| 一个带时间的活动+深度介绍 | 校园活动 | 文章页(填活动信息) |
| 一份可下载的课件/讲义/模板 | 学习资料 | 学习资料页 |
| 一个推荐学生用的软件/工具 | 软件与工具 | 软件与工具页 |
| 一个办事流程/长期说明 | 校园指南 | 校园指南页 |

两条判断技巧:

- **有时间性吗?** 有截止日期、到期即失效 → 通知页;长期有效、内容稳定 → 文章页 / 指南页;
- **是「消息」还是「服务」?** 告诉学生一件事 → 纪事/活动;教学生办一件事 → 指南;给学生一件东西(文件/工具) → 资料/软件。

## 4. 五种内容类型

后台新建内容时会让你选类型,对应关系如下(括号内为后台内部类型名,仅供对照):

| 类型 | 用于板块 | 有哪些内容 | 有效期 |
|---|---|---|---|
| **通知页**(NoticePage) | 校园纪事、校园活动 | 标题、发布部门、摘要、正文、图片、附件、外部链接、受控标签;活动板块下另有活动时间/地点/报名链接 | **必填**,必须是未来时间——到期自动归档 |
| **文章页**(ArticlePage) | 校园纪事、校园活动 | 与通知页相同 | **可选**——不填就长期在线,填了到期自动归档 |
| **学习资料页**(MaterialPage) | 学习资料 | 标题、发布部门、学科·专业方向、资料类型、摘要、正文、外部链接、附件、受控标签 | 不设有效期(常青内容) |
| **软件与工具页**(SoftwareToolPage) | 软件与工具 | 软件或工具名称、发布部门、适用平台、正文、来源链接或第三方网盘链接、授权或费用说明 | 不设有效期 |
| **校园指南页**(GuidePage) | 校园指南 | 服务名称、发布部门、指南类别、地点、开放时间、联系方式、补充说明、责任来源或责任单位、维护方式、最后确认日期或更新时间 | 不设有效期 |

补充说明:

- **发布部门**是所有类型都必填的,而且必须与你所在(被授权的)部门一致——这是网站「谁发布、谁负责」的基本规则;
- **活动信息**(开始/结束时间、活动地点、线上活动、报名链接)只在**校园活动板块**下出现并要求填写;同样的类型放在校园纪事板块下就不需要、也不允许填活动字段;
- **受控标签**只能在管理员预先建好的词表里选,不能自己随手造新标签(保证全站标签口径统一);
- **附件(文档文件)**的格式与大小有限制:支持 doc/docx/pdf/ppt/pptx/xls/xlsx,单个不超过 20 MiB;当前部门账号**不能自行上传文档附件**,需要附件时请把文件交给总管理员协助上传;
- **图片**支持 jpg / jpeg / png / webp,系统会自动检查文件类型是否与实际内容一致。

## 5. 发布前准备

动手建草稿之前,把料备齐:

- [ ] 文字定稿:标题一句话说清事情;摘要 1–3 句;正文分段,先说结论后说细节;
- [ ] 图片(如需):jpg/png/webp 格式,内容与文字相关,分辨率够用但别用原相机直出的大图;
- [ ] 外部链接(如需):在浏览器里点开确认能访问、内容合适;
- [ ] 附件(如需):确认格式与大小在限制内,交给总管理员上传;
- [ ] 活动信息(活动内容):确认开始/结束时间准确,线下活动确认地点全称;
- [ ] 名义确认:以哪个部门的名义发,部门负责人是否知情同意;
- [ ] 保密检查:不含学生个人信息(如完整学号+姓名组合)、不含内部文件、不含未公开的决定。

## 6. 内容生命周期(发布之后会发生什么)

每条内容都有生命周期,学生看到的状态由系统自动管理:

```
草稿 ──发布──> 已发布 ──到期──> 已归档(标注「已过期」)
  │               │
  │               └──手动下线──> 已下线
  └──定时发布──> 到点自动变为「已发布」
```

- **草稿**:只有后台能看到,学生看不见;
- **定时发布**:可以预约将来的时间上线,到点系统自动发布(适合「周一早八准时公布」这类场景);
- **已发布**:学生可以在板块列表、搜索里看到;
- **已到期**:到达你设置的有效期后,内容**不会消失也不会被删除**——它从默认列表退场,进入该板块的「历史归档」页,学生搜索仍能找到,打开时页面顶部会标注「已过期」;
- **已下线**:需要提前撤下时用「下线」——同样不是删除,内容还在后台,随时可以修改后重新发布;
- **归档/下线 ≠ 删除**:任何内容都不会被系统自动删除;**永久删除只有总管理员能做**,且仅限极少数情形。**不确定时,永远选择「下线」而不是请求删除。**

## 7. 发布前检查表(30 秒)

发布之前逐项过一遍,全绿再点「发布」:

- [ ] 标题准确、完整,能独立看懂(不依赖正文);
- [ ] 摘要与正文没有错别字、日期时间正确;
- [ ] 发对了板块、选对了内容类型;
- [ ] 发布部门正确;
- [ ] 活动内容:开始/结束时间正确,线下活动有地点;
- [ ] 通知内容:有效期已设置且是未来时间;
- [ ] 图片能正常显示,附件链接有效;
- [ ] 外部链接已经点开验证过;
- [ ] 无涉密、无个人信息、无未定稿内容;
- [ ] 用「预览」看过实际效果。

## 8. 发布之后

- **前台复核**:以访客身份打开刚发布的内容,检查排版、图片、链接;再在站内搜索里搜一下标题,确认能被搜到;
- **内容有更新**:直接在后台修改并重新发布即可;每次修改都会留有修订历史(由系统自动保存,不需要你操作);
- **需要撤下**:用「下线」,不要请求删除;
- **活动结束 / 通知过期**:不用做任何事——系统会自动归档;若确需提前撤下,执行「下线」;
- **发现发错板块或类型**:联系总管理员处理(板块与类型在发布后不宜自行改动,以免链接与分类混乱);
- **首页推荐位 / 紧急提示**:由总管理员统一维护,有需要请联系;
- **内容反馈**:学生通过页脚的统一反馈邮箱反映问题,运营人员收到后按「先核实、再修改」处理。
