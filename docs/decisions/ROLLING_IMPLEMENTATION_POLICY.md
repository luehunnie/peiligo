## 1. 指令原文（Human，2026-08-18）

> 已冻结并通过对应 Gate、且不依赖未来未决设计的内容，允许提前进入正式实现；未来未冻结设计不得由代码提前代决。旧规则「G2 前禁止正式代码/骨架/依赖锁定」需最小同步。

## 2. 政策要点

1. **允许范围**：同时满足 ① 设计已冻结（如 ADR 已 Accepted、设计文档已过对应合并门）；② 已通过对应的 Gate（如 G1）；③ 不依赖未来未决设计——的内容，允许提前进入正式实现，不必等待 G2 关闭。当前已具备条件的实例：MB1「干净骨架、锁定依赖、settings 分层、测试库护栏」——其依据 ADR-0001（版本组合）与 ADR-0003（干净骨架）均已随 G1 置为 Accepted（引证 `docs/decisions/G1_ARCHITECTURE_FREEZE.md` §2）。
2. **禁止提前代决**：未来未冻结设计不得由代码提前代决——未冻结、未过门或待决策门（如 ADR-0006 中文搜索后端、G2 条件 ⑤ 待确认参数表）的内容，不得以任何提前落码形式成为既成事实裁决。
3. **G2 语义不变**：G2 仍为完整架构领域 + 治理基线准备门（00 §6 G2 行 = 02 §10 七条 + 治理输入；00 §15 执行细则），本政策不削弱、不移除、不重排该门；G2 通过条件与未通过时的阻塞语义不变。仅修正一种读法：G2 不再被读作一切正式代码的绝对起点。
4. **MB1+ 计划仍为详细实现参考**：03 线（MB1–MB18 及其后）各步骤的规格（阶段目标/输出/验收命令/审查要求）仍是提前实现工作的详细实现参考与验收口径来源；提前实现不豁免全程红线（OR-1..OR-6、02 §0.2 版本与「不改核心」约束、PRD §20 V1 不做清单、秘密纪律、PVE/生产逐项授权）。
5. **PRD 与 Accepted ADR 不受影响**：`PRODUCT_REQUIREMENTS` 与 ADR-0001..0005（Accepted）零改动；ADR 状态此后仍仅可由项目负责人执行 `Accepted → Superseded` 流转。
6. **DAG 不变**：不新增、删除或重排任何步骤、门或依赖；提前实现是 DAG 之外的并行治理通道，不改变 00 §5.2 表内依赖列与 03 线门语义。
