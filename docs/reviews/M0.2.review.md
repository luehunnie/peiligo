## 2. 双口径发现清单

### F-01（B3）· `.gitignore` 以 `.env` + `.env.*` 两行实现 `.env*` 模式族，无点分隔后缀的边缘形态不被覆盖

- **级别**：P2。
- **位置**：`.gitignore` L3–L4。
- **问题**：M0.2 步骤块「输出」要求 `.gitignore` 含 `.env*` 模式；实现采用 `.env` 与 `.env.*` 两行。该两行集合是 `.env*` 全局的真子集：`.env.local`/`.env.production` 等常规形态均覆盖，但无点分隔后缀形态（如 direnv 的 `.envrc`、`.envbak`）不命中任何一行，若未来出现此类文件将不被排除。
- **证据**：`git check-ignore` 实测——`.env`/`.env.local`/`.env.production` → IGNORED；`.envrc`/`.envbak` → NOT ignored（§4 命令 12）。
- **影响**：当前仓库不存在任何此类文件（`git status --ignored --porcelain` 仅 `.DS_Store`×2 与 `.local_backups/`，见命令 11），且项目工具链无 direnv；属理论性边缘缺口，验收命令原文「`.gitignore` 含 `poc/` 与 `.env`」字面通过。
- **建议**：不在 M0.2 返工（本步骤已完结、改动即越界）；在 M0.5（SECRETS_POLICY 固化）将 `.env`/`.env.*` 收紧为 `.env*`（或在 M0.3 触碰 `.gitignore` 的 D8 窗口顺带处理），并同步修正 manifest §5 表述（见 F-02）。

### F-02（B4/manifest）· manifest §5「覆盖 `.env` 与 `.env*` 模式」表述在集合口径上略有不精确

- **级别**：P2。
- **位置**：`docs/decisions/M0-2-BASELINE-MANIFEST.md` §5（L50）。
- **问题**：manifest 声称 `.env` + `.env.*`「覆盖 `.env` 与 `.env*` 模式」；实际上两行集合 ⊂ `.env*` 全局（差集即 F-01 的无点后缀形态），「覆盖 `.env*` 模式」的等式不严格成立。
- **证据**：`.gitignore` L3–L4 原文；`git check-ignore .envrc` → NOT ignored（F-01 同源）。
- **影响**：无执行风险；仅文档精度问题，且根因与 F-01 同一。
- **建议**：随 F-01 一并在 M0.5 修正表述（或在后续触碰 manifest 的步骤更正），无需为此单独返工。

### F-03（A2）· manifest「12 个基线文件」计数口径所引派发契约文本为仓库外事实，仓库内不可独立核验（追溯性观察）
