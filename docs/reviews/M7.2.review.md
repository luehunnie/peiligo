## 4. 关键发现（全部非阻断；按严重度排列）

> 依 00 §4.6 规则 5 口径：以下均不构成拒绝或条件通过事由——未命中任一阻断性检查（PRD 缺失/自造阈值/位点表不一致/隐私扩大/E1 失实/参数散落/容量冒认/STATUS 虚标/秘密）。F-1 建议随 G2 前微修或并入下游 MB 批次处理，不扩围。

### F-1（中等）§3.2「archive 规则」句与 PUBLISH §7 可见性总表不符；历史归档视图的 SEO 口径无归属

- **事实**：NFR §3.2 称「到期内容**仅经 #7 搜索态（HISTORICAL）可见**并带『已过期』标注…该态整体 noindex」。而 PUBLISH §7 前台可见性总表（PUBLISH:248-256）给出 expired 的**三个**前台消费位：①板块历史归档视图（HISTORICAL，PUBLISH §6.1 语义已冻结、URL 留 B 阶段）；②站内搜索（ARCHIVE-SEARCH，§7.1）；③具名 URL 直达（§6.3 裁决，载体① 原slug放行 / 载体② 保持404 留 B 裁定）。
- **影响**：历史归档视图是已冻结语义的未来公开页面，但未入 §3.1 位点表（该表与 IA §10 逐行一致，无过错），其 robots/sitemap 处置在 IA §10（先于 M5.2）、PUBLISH §6.1 与本文三处均未认领——若 MB8–MB9 实现时无约束，将产生「已过期内容新收录面」，恰好撞上本节自己「已过期内容不产生新收录面」的断言；且 NF-11 仅核八行，检不出该面。
- **最小修复建议**（不扩围）：§3.2 改述为「expired 消费位＝历史归档视图＋搜索态（具名 URL 载体随 B 阶段裁定）」，并在此登记一句义务：「历史归档视图实现时强制 noindex 且不入 sitemap（随 MB8–MB9 验收）」——或将该处置显式挂入 §12 待确认体系。

### F-2（低）HISTORICAL / ARCHIVE-SEARCH 术语混用

- §1.4 行 5 与 §3.2 把「/search/ 命中已过期条目」的态称作「HISTORICAL 态」。冻结术语（CONTENT_MODEL §16.4、PUBLISH §6.2-3/§7.1）：搜索口径＝**ARCHIVE-SEARCH**，HISTORICAL＝**历史归档视图**口径。§1.4 行 5 已正确并注「M5.2 ARCHIVE-SEARCH 绑定」，建议统一改用 ARCHIVE-SEARCH 指称搜索态，避免 B 阶段实现/测试按错口径落位。

### F-3（低）§1.3 服务端 p50/p95 行引注未区分「取样协议」与「计时范围」的来源

- 「冻结依据＝M6.1/POC §4.2 冻结定义」对取样协议（预热+20 次、分位取值）属实；但「计时＝视图执行+模板渲染墙钟」是本文**新定**的端到端范围——POC §4.2 明示其计时「不含模板渲染——M7.2 端到端口径另测」。本步定义之正是预留动作、且方向更严（含渲染只会更慢，不放松任何门槛），不构成自造；建议引注拆分为「取样协议＝POC §4.2；计时范围＝本文端到端新定（POC §4.2 预留）」以杜绝误读。

### F-4（低）`WAGTAILADMIN_BASE_URL` 占位值文件归属

- §3.2 称占位值 `http://example.com` 为「production.py 现状」；实际定义于 `base.py:242`（production.py `from .base import *` 继承且未覆盖）。实质结论（占位值生效中、部署阶段配置、随 PP-19）正确，建议改引 `base.py:242`。

### F-5（低）三个测量协议默认数值无上游出处且未入 PP 表

- Lighthouse「3 次运行取中位」（§1.3）、并发混合场景「4:3:3 配比」（§1.3；PP-10 行文未含该细节）、NF-13「连续 ≥7 天成功记录」证据窗。均为验证方法细节、不放松任何 PRD 阈值，按「关键数值」口径不判违规；建议随 PP-10/PP-23 确认时一并冻结，或在文中标注「方法默认」。

### F-6（低）NF-17 复验门 hit@10＝30/30 严于 ADR-0006 冻结决策门（≥90%）

- 与 M6 实测全对（POC §5.2 三档均 30/30）一致、属回归门加严，方向安全；建议加注「严于决策门、取实测全对口径」，避免被误读为对 §4.4 冻结判据的变更。

### F-7（低）§9 可追溯性表缺 PRD §12 第三句映射行

- PRD §12「站内不得发布个人敏感信息或面向内部的保密材料」未在 §9 出现。其归属为 SB §4.5「禁止上传敏感数据（治理红线）」（内容治理约束，非 NFR 测量项，SECURITY_BASELINE.md:203-205），建议 §9 补一行显式划出（同「视觉规范」行的处理方式），使 PRD §12 映射零缺行。
