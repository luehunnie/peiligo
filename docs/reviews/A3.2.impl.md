## 4. 关键技术口径与留痕（wagtail 7.4.2 源码亲证）

1. **S1 挂修订级**：`scheduled_revision`＝`revisions.filter(approved_go_live_at__isnull=False).first()`（draft_state.py L176-177 官方谓词）；E3/E7/E8 均不清对象级 `go_live_at`（publish_revision.py/unpublish.py 亲证），残留三序列测试固化"残留不得把 S3/S4 误判 S1"。
2. **publish 分支读修订重建实例**：`PublishRevisionAction.__init__` 即 `revision.as_object()`——分支条件用**修订内容**里的 go_live_at；对象列仅编辑表单保存或发布动作 object.save() 写入。测试口径：预约须在 save_revision 前设实例 go_live_at（随内容序列化）。
3. **动作后实例失效纪律**：发布类动作改写重建实例，本地实例 live/expired 过期→一律 `refresh_from_db()`；且 `scheduled_revision` 系 **cached_property 不随 refresh 失效**（发布前读过即缓存 None）→ 判 S1 前取新实例（`NoticePage.objects.get`）。测试注释留痕，两次真实踩坑记录。
4. **E3/E7 测试时间机制**：`mock.patch("django.utils.timezone.now")` 包住 `call_command("publish_scheduled")`——仅回拨 `approved_go_live_at` 不足（修订内容 go_live_at 同为分支门控）；E7 到期用 queryset update 回拨对象级 expire_at（绕 clean 未来性模拟时间流逝）。
5. **删除守护用钩子非覆写**：DeletePageAction 调 `super(Page, specific).delete()`（treebeard MP 子树硬删），子类 delete 覆写被绕过；`before_delete_page` 返回响应即取消（admin/views/pages/delete.py 亲证）＝§17.4"clean/hook 拦截"的实现半边。
6. **E11-S4 观察**（A3.2-D 留档）：expired→E11→E4 取消后按 §14.2 推导落 S4 而非预约前 S3——本批以专门测试坐实真实行为（留档观察的"仅观察不阻断"定性经实测成立），建议 B 阶段随 PS-17 一并复核后台动线。

## 5. 结论

§14–§19 当前可实现部分全量落地：五状态零字段纯推导、三政策发布窗口单闸口、CURRENT_DEFAULT 三前台消费位、到期保留、删除政策三路（钩子拒删/PROTECT/through 级联）。PS-10..29 全数映射（实现+测试或设计登记），E1–E11 逐边含非法闭集反例。回归八项全绿、零迁移漂移、§1–§13 与 Accepted ADR 零触碰。建议独立审查关注：§3 映射表逐断言、E11-S4 留档口径、`current_default_pages` 消费位完整性（V1 是否尚有第四消费位）。
