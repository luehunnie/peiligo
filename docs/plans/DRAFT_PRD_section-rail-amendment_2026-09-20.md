# DRAFT PRD 修订：首页分区文章模块 → 单行横向滚动轨道（SPEC-003 #50）

- 状态：DRAFT（随 PR #54 提交评审；不改变「每 Spec ONE Final PR」）
- 日期：2026-09-20
- 触发：Human 人工验收反馈（本地生产方式预览 localhost:4400）
- 执行记录：upgrade Issue #50（本修订对应评论为唯一执行状态）

## 1. 原口径（被本修订取代的部分）

PRD B（#48 冻结）的响应式条款：「手机单列、≥601 两列、≥981 三列
（601/761/981 断点体系）」。

## 2. 新口径（Human 验收裁定，2026-09-20）

Human 反馈原文要点：

1. 「我们有5个分区但是只展示了4个（我觉得两排是用户容忍度的极限），
   我觉得你可以考虑做成单行的可滚动的条，这样视觉重心也不会被拉走」；
2. 校园网站实际五板块（以截图为准，顺序固定）：**校园纪事、校园活动、
   学习资料、软件与工具、校园指南**；
3. 「我还是要强调优先手机适配，但是电脑适配也不能忘」。

Controller 裁决：采纳**单行横向滚动轨道**，取代多列换行口径。

### 2.1 布局规则（取代原响应式条款）

- 五张分区卡片置于**一条横向滚动轨道**；任意视口（含中间宽度）恒为
  **单行**，不多行换行；**外层页面不得出现横向溢出**。
- **手机优先**：手指横滑为主交互；**下一卡边缘外露**作为可滑提示；
  卡宽 `min(82%, 320px)`（390 视口 ≈ 273px 卡 + 63px 露边）；轻吸附
  （scroll-snap proximity）；overscroll-behavior:contain 防横滑误触
  浏览器历史导航。
- **桌面不忘**：鼠标滚轮/触控板横移可用；滚动条细线化（--line 色）；
  轨道为**可聚焦滚动区**（tabindex=0 + role=group + aria-label），
  键盘方向键原生滚动即可达全部分区——全部标题链接本身也在 Tab 链中。
  仅 CSS/原生能力，**零 JS、无轮播按钮**。
- 宽屏一行约 3 张整卡 + 尾部露边：信息密度不降、视觉重心不被拉走。

### 2.2 不变项（PRD B 其余条款全部维持）

每分区一张轻量卡；内部固定 3 篇标题空间（不足留白、不收缩、不填充）；
首发降序（服务端顺序原样消费）；仅可点击标题；**0 篇分区不渲染**
（Human 未撤销；本轮反馈中的「只展示4个」系演示数据所致，默认演示
数据改为五分区全有文章，软件区默认可见）；克制视觉、仅既有 token；
不改顶部五入口导航与校园快讯布局；仅 Astro、零后端。

### 2.3 名称与顺序口径

B 模块展示顺序 = `home.sections` 数组顺序（现状与 Human 截图顺序
一致）；分区名称一律取自现有内容接口 `section.title`，前端不硬编码。
**事实记录**：现后端（E3/夹具）五分区名称为 昆社纪事/活动预告/
学习资料/软件与工具/校园指南，与 Human 截图（校园纪事/校园活动/…）
存在内容差异——属 CMS 内容层事务，冻结期内前端不改后端数据/URL
slug；本地演示数据（mock 覆写，非仓库契约夹具）按 Human 名称呈现，
线上名称以 CMS 实际数据为准（差异已在交付报告中原样呈报）。

## 3. 验收口径

- 任意宽度（390/768/1440 + 600/601/980/981 边界）：单行、页面无横向
  溢出、恰好一张卡部分外露、轨道内可滚动；
- 键盘：轨道可聚焦、方向键可推进（原生滚动区）；
- 原 PRD B 全部内容规则（3 槽/留白/排序/仅标题/0 篇隐藏）回归通过；
- 截图存证（首屏＋滚到末）：`webapp/docs/evidence/spec-003-r1/`；
  断言为实值断言（computed + 几何），截图经目视核查。
