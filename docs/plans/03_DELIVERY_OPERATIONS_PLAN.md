## 1. 全局治理规则（适用于所有步骤）

### 1.1 单步骤对话边界（模板）

每个步骤 = 一个独立代理对话（PRD §24.2）：

1. **下发**：组内总控（Orca）以任务契约启动对话，契约含：目标、输入文档路径、允许修改文件范围、验收命令、测试要求、完成报告格式。
2. **对话内**：实现 + 自测（验收命令在自己的 worktree 内全部通过）+ 完成报告（3 句执行摘要 + 证据路径）。
3. **结束**：`worker_done` 后对话终止；**不得在同一对话延伸到任何相邻步骤**。
4. **返工**：审查意见修复、验收失败返工必须开启新对话，引用原步骤编号与审查报告路径；修复对话只做修复 + 回归测试，不顺带扩展。
5. **歧义处理**：对话内遇到需求歧义或前置输入缺失，用 `ask`/`decision_gate` 向上提问（PRD §26：不静默假设）。
6. **越界处理**：发现必须修改范围外文件才能完成时，停止并上报协调者重新签发契约，不自行扩界。

### 1.2 工作树与分支

- 每个实现类步骤使用独立 Git worktree + 分支 `build/sNN-<slug>`（00 修订 12 统一前缀），基于重建基线分支 `rebuild/v1`（peiligo_restart 内）。
- 合并顺序按 §3 DAG；两个待合并分支触及同一文件时，后合并方 rebase 后重跑自己的验收命令再合并。
- 只读调查/验证类对话（如 S20 验证、S22 证据整理）不创建分支（PRD §24.4）。

### 1.3 文件范围与互斥

- 步骤契约中的"允许修改文件范围"是硬边界；范围外文件只读。
- **共享文件清单**：`settings/*`、项目级 `urls.py`、`templates/base.html`、根依赖清单（`requirements*.txt`/`pyproject.toml`）、`.github/**`。触碰共享文件的步骤必须在其范围中显式标注"（共享）"，该类步骤之间不得同时处于实现中；各自 worktree 可并行开发，但**合并入 `rebuild/v1` 时按到达顺序串行合并**，后合并方负责 rebase 解决冲突并重跑验收命令。
- 不允许两个代理并发修改同一文件集合（PRD §24.3）。项目级 `urls.py` 应在 S1 固化为按 app `include()` 的装配式结构，后续步骤只新增各自 app 的 `urls.py`，以最小化共享文件触碰。

### 1.4 独立审查（v2.1 风险分级；按步骤风险级执行，R1+ 合并前必备）

- **R0**（文档局部小改）：GLM-5.3 实现 + 验收命令/自动验证，免独立审查（实现者自审留档于完成报告）。
- **R1**（普通步骤）：GLM-5.3 实现 + **独立 GLM 新会话**审查。
- **R2**（跨模块、状态机、权限/发布/安全复杂步骤）：GLM-5.3 `high` 推理实现 + 独立 GLM `high` 新会话审查。
- **R3**（架构级）：在独立 GLM 审查外另加 GPT 压缩 Risk/Architecture Review。
- **R4**（高影响/不可逆，如 S23 生产）：GPT 决策 + 项目负责人 Human Gate + GLM-5.3 执行。
- 独立审查一次覆盖双口径：需求/架构（对照 PRD 条目与冻结 ADR 逐项核对；检查越界——改核心、扩 V1、破坏权限模型、偏离信息架构）与实现/测试/安全（代码质量、测试真实覆盖——审查者必须亲自运行验收命令与测试套件、安全面：权限、输入校验、秘密处理、注入面）；结论为通过 / 有条件通过（列条件）/ 拒绝（列理由）。
- **实现者不得担任审查者（实现者不得成为唯一审查者）；审查必须新开会话，不得继承实现对话上下文**（PRD §24.3，v2.1）。
- 审查报告：`docs/reviews/<步骤ID>.review.md`（R1+ 必备）；R3/R4 另落 `docs/reviews/<步骤ID>.gpt-review.md`（00_MASTER_PLAN §4.6 与修订 11 v1.3 口径；D8 裁决后以其为准）。
- GPT 可用性规则（FIX-02/v1.4，执行契约全文见 00 §4.6 规则 6，本条仅摘引）：R0–R2 GPT 不参与、GPT 暂无额度不阻塞任何步骤与门；R3 重大裁决原则上等待 GPT Risk/Architecture Review，跳过仅限项目负责人对**一个具体 R3 Task** 发一次性 `R3_GPT_WAIVER`（记录 TASK/REASON/HUMAN_APPROVAL/DATE，不可复用、不可泛化，不存在全局自动替代规则）；R4 GPT 不可用时**默认 BLOCKED**，等待 GPT 可用与 Human 批准，禁止任何全局 GPT 缺席旁路。

### 1.5 证据与秘密

- 完成报告、审查报告、验证数据入 Git 的范围按 D8；未入 Git 的注明本地路径与保留期限。
- 代理禁止读取/输出凭据文件与真实 secrets；报告中出现的环境值必须脱敏；曾暴露令牌的轮换遵循综合审计 P0 处置结论。

### 1.6 环境与授权矩阵

| 环境 | 用途 | 操作授权 |
| --- | --- | --- |
| 本地开发机 | 开发、自测、本地容器验证 | 无需额外授权；不得接触真实用户数据与生产凭据 |
| CI（仓库托管方） | 合并门禁 | 无需额外授权；仅使用哑密钥 |
| 校园网 PVE（Ubuntu VM + Docker） | 测试/预发布（PRD §16：PVE 不是生产） | **每次会话需用户明确授权**：VM 创建/变更、部署、恢复演练 |
| 正式生产服务器（校方另一台服务器） | 正式服务 | **每次操作需用户明确授权；G4 批准前禁止一切生产操作** |
| 校园 DNS / 证书 / 邮箱系统 | 上线配置 | 需用户授权并由用户/校方协调 |

### 1.7 通用回滚

- **代码**：worktree 分支废弃（未合并）或 revert 合并提交（已合并）；revert 后重跑受影响步骤的验收命令。
- **迁移**：优先编写可回退迁移；必要时 `python manage.py migrate <app> <上一版本>`；不可逆迁移执行前必须先备份并记录。
- **数据（预发布/生产）**：使用步骤前备份恢复；生产恢复目标为故障后 24 小时内（PRD §16）。
- **配置**：settings/中间件类变更尽量提供开关，紧急回退用开关而非改代码。

## 10. 本计划自身的不确定项

1. 本文件假设的综合审计证据倾向（服务端模板、容器权限树、7.4.2 LTS 组合、同仓库干净骨架）**均为缺省假设，以 P3–P8 冻结裁决为准**；若裁决不同，受影响步骤的目标/文件范围由组内总控（Orca）按裁决重签契约，DAG 结构不变。
2. 步骤粒度按"一个代理对话可完成"估算；若实施中某步骤实际超出单对话规模（最可能为 S3、S8），由组内总控（Orca）拆分为 `S3a/S3b` 等子步骤并保持本文件其余约束不变，同时在文档变更记录中登记（PRD §25）。
3. CI 托管选型（GitHub Actions 缺省）与仓库可见性（决策门 6，按私有管理的现状）可能影响 S15/S19 细节；以 D8/D9 裁决为准。
4. 性能测量的数据规模口径依赖 U2（部门数量与内容量级），S20 前须由项目负责人确认规模假设。
