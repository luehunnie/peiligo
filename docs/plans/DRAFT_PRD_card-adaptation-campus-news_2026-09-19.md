## 2. 需求 A：首页轮播长文字切换增高 bug（最小修复）

### 2.1 症状
首页轮播标题字数过多时，切换轮播出现卡片异常增高/布局跳变；据原报告仅在"位于首页、能完全看到轮播图"时触发（该机理**未证实**，§7）。

### 2.2 已确认约束
- 改动保持最小，只修此 bug；不扩为全站统一截断、响应式重设计、顺手重构。
- 标题简略显示仅在本 bug 修复**必要处**最小采用；文章详情页保持完整标题；Wagtail 源数据/CMS 不改。
- 具体根因仍须证据，**勿先假定统一固定高度方案**（预留高度/钳制/过渡等取舍待证据与 Spec 阶段定）。
- 移动端优先验证，兼顾桌面现有行为。

### 2.3 关键复现背景（Human 报告的现状，2026-09-19）
「因为在目前上线版本中，我已经减少了字符数，才避免了这个bug。」——线上系**人工缩短标题字符暂时规避**，不是代码修复；线上当前未观察到跳变**不能否定本 bug，也不能充当修复验收**。原则：正常内容维护不应再靠人工缩短标题绕过布局缺陷。不得要求把线上标题改长/恢复历史内容；不改 CMS；不杜撰原始长标题内容/确切阈值。

### 2.4 验收方向（本地/测试环境；Spec 阶段细化）
在本地/测试环境构造足够长标题与**长短交替**轮播：移动端优先＋其他视口下，切换高度稳定、简略显示符合预期；覆盖**完全可见/部分可见/离开后返回**等条件。mock 机制复现（§5）仅证明机制存在，不当作线上全部根因已确认。

- **容量规则已决**（Human：「永远保持显示三篇的固定大小，不足三篇不足的部分就空着」）：每张分区卡片**始终保留 3 条文章的固定容量与空间**；仅 1/2 篇时**其余位置留白**——不收缩卡片、不填假文章、不显示占位文字、不创建空可点击项；"固定大小"＝**同一响应式布局内按 3 条容量保持空间稳定**，非所有设备强制同一像素宽高；**0 篇分区不展示**（沿用既有"空分区隐藏"决定，本条仅针对已展示分区的不足 3 篇情形）。
- **已认可布局方案**（Human：「我同意你的方案」）：
  - 每分区一个**轻量卡片**；
  - 卡片顶部＝**分区名称＋"查看全部"**；
  - 卡内列出该分区**最新 3 篇文章**；**每篇仅显示可点击的文章标题，不显示缩略图、日期、摘要、作者、标签等任何附加文章信息**（Human 2026-09-19 续：「我的建议是直接展示文章标题，其他什么都不用展示。最简单。」；此为文章行层级决定，**不取消分区分组**——轻量卡片/主题色/分区名称/查看全部/手机单列宽屏分列均沿用）；
  - 视觉＝浅边框、留白、细分隔线；**克制但有美化**，分组、对齐，文章多时不显杂乱、不抢首页重点；
  - **手机单列，宽屏适当分列**（原"移动端展示形态"待问已决）；
  - **沿用现有设计**（现有设计语言与 token，见 §4）。
- **配色要求**（Human）：每个分区有不同的主题色，方案需考虑；同时 Peiligo 本身存在品牌主题色。现有分区色/品牌色的真实定义见 §4；**具体着色位置属建议（§3.3），Human 未指定**。

### 3.3 布局与配色建议（GLM/Controller 建议，非 Human 指定；随 Spec 细化）
- **品牌青（--teal）维系统一身份与公共操作**：模块标题、"查看全部"等链接类元素沿用既有链接色。
